旧方案中的 manifest/protocol v1 已过时。当前源码常量和兼容清单确认：SDK crate 0.1.0、manifest v2、protocol v2、middleware v4、upstream_adapter v2。SDK 识别 middleware v3/v4 和 upstream_adapter v1/v2 声明；本地中间件执行桥目前只接受 v4，适配器已有 v1 请求输入转换。声明识别或局部转换不能代替完整旧版制品验收；兼容清单及弃用计数要按本分支实际支持情况维护，不能照抄上游已走过的发布次数。

这是网关服务端插件，不是 Codex 桌面插件。上游采用 trustedProcess 完整信任模式：进程以宿主系统身份运行，没有代码沙箱，能力声明和 iframe 都不能隔离进程对凭据、文件和网络的访问。宿主仍须维护正常 API 的身份、账本及资源生命周期合同。

## 本地最重要的适配差异

### 预算与资源归属

本地 `gateway-store/src/postgres/client_budgets/mod.rs` 以 `(user_id, account_group_id)` 作为预算作用域，多个 Key 共用 `user_group_budget_windows`。上游 `host.keys.update_budget_limits/reset_budget` 按单个 Key 处理。

不能把上游 Key 重置直接映射为清空用户共享额度，也不能悄悄建立第二套 Key 账本。首版对这些写入方法明确返回不支持；查询如提供共享预算，必须暴露准确作用域，不能假装成独立 Key 配额。之后为本地共享额度设计明确的版本化接口，额度售卖/分配插件按该合同适配。

插件创建 Key/分组时还需要本地 owner_user_id、用户授权、有效分组和审计 actor；入口 principal 只能映射既有有效 Key，不能变成管理端登录身份。现有用户订阅周期继续由本地 owner 负责，上游撤回外部窗口功能不构成删除本地订阅实现的理由。

### 模型调用与中间件

本地 `DefaultExecutionSession` 已拥有取消安全结算。导入 Prepared Execution、冻结中间件计划、嵌套模型调用时，在同一生命周期内扩展，不能新建绕过账本的执行入口。

- 页面模型调用通过所选 Key 走正常鉴权、账号范围、路由、租约、倍率及结算。
- 父子调用保留请求关联，确定每次真实调用的费用归属，防止父请求和子请求对同一费用重复结算。
- single-use next、惰性正文、流信用、取消与 generation 排空成组适配；流已提交或发送结果不明时禁止自动重放。
- 本地受管身份头、账号归属及原 WS 的 response.interrupt 行为仍由宿主/Provider 最终决定；若与目标插件合同有差异，明确记录，不能承诺任意上游插件原包兼容。

### 安装、页面与版本

新增 SDK、Runtime、plugin-cli；Host 负责分发与进程资源；Admin/API 负责业务用例和管理入口；Store 保存制品、来源凭据、实例、敏感配置、版本快照、私有状态和资源归属；在 apps/gateway 组合。

上游前端已依赖 `@codex-proxy/ui` v0.3.2 和 pnpm 12.6.0。本地移植插件页、iframe 桥及相关 API，优先适配现有基础组件，不连带迁移整套用户界面与依赖。

本地 0001–0026 迁移冻结；按实施时最大编号追加插件迁移，当前从 0027 起。上游 0018–0020 只作为结构参考，不复制编号、旧基线或迁移合并历史。

版本范围与可执行合同分开处理：上游目前对宿主范围/能力版本不匹配提示警告，包格式、平台、RPC 握手错误仍阻止启动。本地首版未实现的能力应明确拒绝使用，不能通过跳过握手或伪报版本启用。兼容策略差异写入支持矩阵。
