# Turn-state 维护边界

## 账号开关与预算

入口：状态维护 → 维护配置 → 账号与模型。
指纹收敛仍在「账号管理 → 更多操作 → 指纹 / Turn-state」设置；
该窗口保留接管快捷开关，但不再编辑维护预算，避免两处维护同一份表单。

- 指纹收敛与 turn-state 接管互相独立，默认关闭。
- 每账号每小时默认最多 **30 个上游探测请求**，范围 1–600。
  候选采集与业务出口验证分别计数。发送前通过 PostgreSQL CAS 预占；
  崩溃、超时或不确定结果仍保守计数，不自动退款。
- 预算从该账号首个预占开始计时 3600 秒，保存在原有加密 State 文档中。
  手动刷新、策略修改、重启、进程切换均不重置预算。
- 默认空闲 3600 秒后不再自动探测。0 仅解除手动维护项的空闲限制；
  自动发现项仍采用 3600 秒。显式“立即刷新”可越过空闲/候选充足等待，
  但不能越过预算、上游冷却、账号权限或暂停状态。
- 自动发现默认关闭，必须显式选择代理池。只从真实业务的精确上游模型发现，
  每账号最多 8 项、全局最多 128 项；探测本身不更新业务活跃时间。
  空闲且已无有效候选的自动项可被回收，手动项和暂停项不自动回收。

旧前端不发送 `maintenance` 时保留原账号维护配置。新增账号配置示例：

```json
{
  "accountId": "account-id",
  "revision": 3,
  "fingerprintConvergence": true,
  "takeover": true,
  "maintenance": {
    "maxProbesPerHour": 30,
    "idleSeconds": 3600,
    "autoModels": true,
    "poolId": "pool-id"
  }
}
```

本次仅新增 `0024_state_probe_records.sql`，不修改已发布 SQL。升级可读取旧 State 文档；保存新账号维护字段后，
旧版二进制不一定能读取新文档。正式发布前应备份原 State 配置，
回滚不能只替换二进制而忽略配置格式。

## 身份与有效期

候选绑定本地账号、上游用户/账号、访问令牌和安装身份的域隔离 HMAC；
不再把会被 Cookie CAS 更新的 `credential_revision` 当成身份。
Cookie 更新不会撤销候选或延长到期时间；更换鉴权身份后不能使用旧候选，
旧鉴权请求的迟到结果也不能重新填充候选池。

历史仅保存 revision 的候选采取保守兼容策略：revision 不符就不能使用，
不会自动改绑到新身份。修改候选长度/块数、TTL 或出口配置会撤下旧值；
改名称、并发、重试频率、预算不延长现有值的绝对有效期。

从 v3.10.1 起，HTTP 与 WS 的新轮次非续接请求都可接管；沿用同一个账号开关，
不是强制 WebSocket 降级。HTTP 通过请求头、WS 通过每次 `response.create` 的
`client_metadata["x-codex-turn-state"]` 发送。WS 接管值不写握手头，不绑定在连接池中。
同轮、`previous_response_id` 与原生续接不重新选取候选，仍按现有会话逻辑传递状态。
WS 已有会话但缺少上一轮或本轮 turn ID 时，不把未知边界当成新轮次进行接管。
复用连接的下一次独立请求会重新检查账号、精确模型、候选有效期与开关，
不会继承上一条请求的接管标记；其他 metadata 与用户正文保留。
非对象 `client_metadata` 无法安全投影 WS 状态时不接管，不把它强改为对象。
维护探测仍使用 HTTP，WS 返回值只用于本次观测/会话，不自动加入维护候选池。
没有候选、返回 312 或形态不匹配不会停用业务账号。长度不能证明模型能力。
重新 OAuth 授权还会校验 ChatGPT 身份，错误账号不会覆盖原凭据。

## 探测与调度

持久化游标进行公平轮询，保留原有分布式租约和全局并发上限。
任务取消/配置改变会停止未完成探测；旧配置结果不能发布。
采集和验证使用同一份冻结的系统画像，不借用最后一位用户的身份。

维护请求和业务请求共享账号实际总并发上限：优先采用账号设置，未设置时采用
当前全局默认值；同时遵守全局请求间隔。不会再用“维护并发 1”覆盖账号总并发。
维护自身受全局探测并发限制，每个调度周期同一账号最多安排一个模型任务。
采集与验证之间仍保留维护专用等待。容量/间隔等待和调度存储错误分别提示，
未取得调度租约不消耗维护请求预算。

真实业务活跃时间先在进程内按账号 × 模型合并，运行时锁繁忙时不会直接丢弃；
持久化 CAS 成功后才确认，跨实例重载只合并待写活跃时间，不恢复已撤销的候选、
已删除的旧自动项或旧开关。该缓冲有界、非持久队列，进程崩溃前尚未提交的活动仍可能丢失。

“账号与模型”选择账号后自动读取该账号模型目录，可搜索、多选或从上游刷新；
按账号白名单/黑名单过滤，不列入图片模型，不跨账号保留旧选择。
模型目录只代表已发现的模型，不保证即时额度或每次上游调用都可用。

必须收到正常 `response.completed`，仅有 HTTP 200 或 token 响应头不算验证成功。
失败/不完整流不会发布候选。401/403/407 暂停维护项，不禁用业务账号；
HTTP 或 SSE 的 429 进入持久化账号级维护冷却，尊重 Retry-After，
不会立即换出口或换模型绕过拒绝。

未入选候选分别记录：未返回 State、结构无法解析、长度/块数不匹配、签发时间超前、
估算剩余时间不足和已有重复值。长度/时间诊断包含实际字符数、块数及按配置 TTL
估算的剩余秒数，不回显原文；默认形态集合仍为 292/10 和 332/12，不自动放行 312。
维护请求正常完成但候选被过滤时，独立探测记录保留实际完成情况和 token 用量，同时记录过滤原因；
正常完成不等于候选成功发布。

代理池支持：

| mode | 行为 |
|---|---|
| `fixed` | 固定出口，每周期最多一次采集 |
| `rotating` | 每次采集新建连接，出口轮换取决于供应商 |
| `api` | 每次采集重新调用 HTTPS 提取接口 |
| `gateway` | 旧配置兼容，等同轮换入口 |

业务出口验证始终走账号自己的出口。IPv4/IPv6 分开诊断；
某一项没有取得 IP 只表示本次未确认，不表示不支持该协议。

## 独立探测记录与页面指标

「状态维护」分为运行概览、探测记录、维护配置。运行概览按账号聚合维护项，
小时预算只展示在账号层；维护配置分为账号与模型、采集代理、全局策略，高级长度规则折叠展示。

新增 `turn_state_probe_records`，不再写入业务请求表、不参与业务使用统计和用户扣费。
采集/验证各一条，保留同一周期 ID、账号名称快照、精确模型、代理池 ID/名称、
HTTP 状态、流完成情况、独立的候选决策、耗时、已知 Token、State 长度/块数/指纹和估算到期时间。
不保存 State 原文、账号凭据、代理 URL 或任意上游正文。

管理员专用 `POST /api/admin/turn-state/records` 支持时间、账号、精确模型、阶段、
处理结果筛选及分页。统计覆盖全部匹配记录而非当前页：采集入选率、验证通过率、
未入选/失败、已知输入+输出 Token（不重复叠加缓存或推理 Token）、未知用量条数与平均耗时。
入选率/通过率只用已知决策作为分母；进行中、历史未知和中断未确认项不伪装成失败。
正常完成不等于候选入选，验证通过不保证后来成功发布；无结果的历史项不伪装为成功。
进程中断未完成的日志在请求截止后 30 秒显示“结果未确认”，不补造 Token 或耗时。
探测记录沿用系统事件保留天数，分批清理，避免无限增长。

0024 将带完整系统探测标记的旧记录迁出业务请求表；保留已知 HTTP/Token/长度等信息，
历史候选决策、原文和出口信息不回填。业务请求、费用与账本不改写。
部署前备份数据库；升级后回退旧二进制将重新写入业务请求表，不建议混跑旧版本。

## 出口 IP 与地区

复用 Host 现有代理检测能力和自定义 CA 策略，检测支持显式代理和服务器直连，
IP 查询与地区解析均有超时、响应体限制，不发送模型请求认证、State 或用户正文。
地区按检测到的具体 IP 查询并校验返回 IP 匹配，不使用代理入口域名推测出口地区。
检测调用现有 ipify / ipwho.is 服务，失败不影响候选验证或业务请求结果。

每次探测保存独立出口检测快照（IP、地区、检测时间、检测来源）。轮换/API 采集每次重新
检测，不读取或写入按入口配置的缓存；只有固定出口及业务出口快照最多缓存 60 秒。
手动测试强制重新检测。旧记录保留当时快照，不回填或改写旧 IP。
辅助检测发生在释放账号并发槽之后，最多等待 6 秒，不占用模型探测预算，
不参与探测模型请求耗时。未知 IP/地区明确显示“未确认/未知”。
轮换/API 代理仅显示“轮换出口参考”；即使固定代理也标注“独立检测快照”，
不把额外建立的检测连接当成上游请求的实际出口证明。
候选未入选或采集网络失败时，轮换入口下一次尝试重新建连，API 模式重新提取代理，
仍受每周期次数、小时预算和请求间隔约束；固定出口每周期只采集一次。
新建连接/重新提取不保证供应商分配不同 IP；不能用独立检测 IP 判断某个出口已被
实际模型请求测试过，也不能据此跳过采集或宣称已换 IP。401/403/407 暂停及 429 冷却不变。
代理手动测试额外展示 IPv4/IPv6 各自检测结果；地区对应其单独标明的快照 IP。
概览展示近 24 小时最近 100 条记录中的账号采集/业务出口快照，未覆盖到的账号不猜测出口。

## 移植范围

选择性适配上游 #148 的 OAuth 身份保护、#152 的最终容量错误交付，以及
#155/#162 和 klno 的生命周期/有界维护思路。没有合并实验分支的 fail-closed
账号调度、第二套 Redis State 权威或定价变更。

#156 的全局/Key 六套客户端画像是独立的大型功能，尚未在本次 State 改动中移植。
当前只明确并冻结维护探测使用的系统画像。后续整合需独立验证用户/Key 权限、
运行时快照、重试和 WS 续接，并从 0025 开始追加迁移（0024 已用于独立探测记录），不能修改已发布 SQL。
