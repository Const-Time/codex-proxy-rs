# 插件安装与管理

管理员可在侧栏「插件」上传 `.tar.gz` 制品，创建实例、填写配置和敏感字段、启用或停用、切换版本、打开管理页面，以及卸载实例。普通用户不能安装或调用插件。

当前已接入 **B：协议与安装管理** 以及 **C：管理页面、私有状态与选 Key 推理**。SDK、CLI、包校验、RPC 和页面桥来自上游 v3.21.2 固定快照 `fb15f3e3`；本地 Admin、Store、API 和运行时接入保持现有职责划分。SDK 包含完整上游类型并不代表本地宿主已实现所有能力。

## 支持范围

| 合同 | 当前支持 |
| --- | --- |
| SDK / 清单 / 进程协议 | SDK 0.1.0、manifest v2、protocol v2 |
| 安装与运行 | 本地上传、摘要与路径校验、配置 schema 校验、独立可信进程、启停与重启恢复 |
| 管理能力 | management v1 的私有资源、页面、已注册路由；仅管理员可访问 |
| 管理请求 | method/path/query/contentType 与二进制正文；不转发浏览器 Cookie 或请求头；响应必须没有自定义头 |
| 页面桥 | 上游 v2 桥的管理请求、Responses JSON/SSE 模型调用与高度调整；本地父页面代为鉴权，iframe 使用独立的 opaque origin |
| 私有状态 | `host.state.get/put/delete`，实例和命名空间隔离，版本比较交换、schema 和配额校验 |
| 只读事实 | management 阶段的 `host.data.keys.get`、`host.data.accounts.list`、`host.data.quota.get`；不含密钥或凭据 |
| 页面推理 | 本人管理员会话显式选择自己的 Key，复用正常 Responses 的权限、路由、预算、倍率和结算 |
| 分组资源 | `host.groups.ensure` 幂等创建实例自有分组，`host.groups.change_members` 增量修改成员；使用真实管理请求的审计身份 |
| Key 资源 | `host.keys.ensure` 幂等创建本人 Key；只绑定一个本实例分组，预算参数校验当前共享额度，不返回密钥明文 |
| 共享额度 | 本地扩展 `host.cpr.shared_budgets.v1.*`：显式用户＋分组查询、整组基础限额 CAS 更新、选定订阅幂等重置 |
| 外部认证 | frontend_authentication v1；单一入口认证器，宿主将外部 principal 映射到现有 Key，沿用正常权限及共享计费 |
| 未开放的能力 | 原生进程 `host.models.*`、middleware、upstream_adapter、路由/选号、公开资源、登录回调、主动额度刷新、Key 预算写入、状态迁移 |

声明未支持能力的插件可保存为停用实例，但不能启用。未实现的宿主回调明确返回 unsupported，不伪造成功。宿主版本范围不匹配显示警告；包平台、摘要、协议或注册清单不匹配会拒绝启动。使用上游插件前须核对这张表；没有验证 workbench 或任意第三方插件的全功能兼容性。

中间件 v4 的单次 `next`、正文透传/改写、事实快照和取消已在 Runtime 内核通过 SDK 子进程验证。管理页可保存停用实例的中间件绑定：request/attempt 挂载、执行顺序、全部请求或指定 Key/分组。顺序较小者先进入，同序号按实例 ID 排序；响应按相反方向返回。分组匹配使用宿主冻结的 Key 授权分组，只选择调用范围，不增加资源权限。Responses JSON/SSE/WS、Images 和 Search 的 request/attempt 数据面挂载已接入验证；执行设置、嵌套宿主调用及其余声明范围尚未完成，上表仍将 middleware 列为未开放；不能把内核测试通过理解为第三方中间件现在可以直接启用。

绑定与实例共用 revision 和配置 CAS。候选升级准备失败仍使用旧代；无法确认配置是否提交时阻止继续使用旧绑定，重新保存确认后恢复。恢复失败的必需中间件保留作用范围内的门禁，进程退出也不自动跳过。启停、绑定和版本变更撤销旧调用计划，包含 RPC 已结束但正文尚未交付的响应。

## 安装、升级与恢复

1. 使用匹配宿主 OS/架构的二进制，通过 [CLI](../backend/apps/plugin-cli/README.md) 打包。
2. 上传并选择制品，填写 JSON 配置；清单声明的敏感字段必须使用独立密码输入框，不能放进普通 JSON。
3. 确认信任该插件及版本后启用。插件采用 `trustedProcess`：以网关系统身份运行，能够访问主机文件、凭据与网络，不是代码沙箱。
4. 切换版本时，候选进程先完成握手和注册，再提交数据库并撤销旧版本入口；候选准备失败保留旧实例。实例 revision 失效后需刷新页面。
5. 停用保留配置和私有状态；卸载要求已停用，并删除该实例及其私有状态。制品单独保留，可在「已上传制品」删除没有实例使用的版本。

单个进程崩溃不会阻止其他实例运行，页面会显示不可用；当前没有自动重启循环，管理员可以重新保存并启用。数据库提交回复丢失时，服务端读取权威记录确认结果；不能确认时停止相关实例，管理员刷新后重新启用，不自动重复插件业务调用。

敏感字段不出现在列表、审计详情或普通日志；留空保留，勾选清除后删除。敏感值保存在 PostgreSQL，未增加独立加密层，数据库备份同样包含敏感配置。不要把凭据填入清单未声明为 secret 的普通配置字段。

## 页面推理

打开插件页面后，点击「查询 Key」并显式选择本人启用的 Key；最多显示匹配的前 100 个，可按名称搜索缩小范围。未选择时管理页面仍可用，模型调用会被拒绝。更换 Key 会重新加载插件页面；关闭页面、切换插件实例或版本会取消该页面的请求，新实例需要重新选择 Key。

页面通过 `window.codexProxyPlugin.models.responses({clientKeyId, body, signal})` 获得标准 `Response`。`body` 是 Responses JSON 对象，`signal` 用于取消。本地宿主额外提供只读 `models.clientKeyId`，仅含所选 ID；父页面拒绝其他 ID。Key 明文由服务端按本人归属解析，只在服务端进入普通 Responses 链路，不传给 iframe 或原生插件。部署级管理 API Key 不能代替个人会话。

插件停用、进程退出或 revision 更换会撤销正在进行的页面推理。Key、用户或账号范围权限变化发布到运行时快照时，同样撤销调用；停用后重新启用不会恢复旧调用。权限比较采用整个 Key 策略，因此其他改变该策略的更新也可能中断调用。已冻结的计费事实不随撤销改写，已取得费用仍按现有链路结算。

每页最多 4 个并发模型调用、正文最多 8 MiB，最长 10 分钟；流采用逐块拉取，每块最多 64 KiB，等待下一次读取或数据超过 30 秒则取消。服务端在页面停止拉取时仍监听撤销，并释放 Core 执行资源。流被取消后不会自动重试。

可运行示例：[推理便笺](../backend/crates/gateway-plugin/sdk/examples/prompt-pad/README.md)。它只声明 management v1，支持发送、流式显示和停止；内容仅保留在页面。已验证 Linux x86_64 的 SDK 构建、CLI 打包、真实进程握手与注册，以及浏览器页面桥对本地 SSE 测试响应的读取和取消；未使用生产账号产生真实模型费用。

## 插件读取宿主事实

可信插件的管理请求可通过 SDK `key_facts`、`account_facts`、`quota_facts` 查询现有数据。这些接口属于管理员安装的全局管理能力，不受页面所选 Key 限定；普通用户没有管理入口，也不会获得这些回调权限。页面选 Key 仍只用于本人模型推理，不能授权账户管理。

Key 查询只返回 ID、启用状态和显式分组绑定；账户查询只返回 ID、Provider、名称、邮箱、分组、启用状态及更新时间。账户列表按 ID 升序分页，`limit` 为 1～100，可按 `openai` / `xai` 筛选，继续查询时传入上一页 `next_cursor`；末页为 `null`。空分组表示没有显式绑定，不代表全账户权限。

额度查询只读取 Provider 已有观测，返回观测时间、窗口标识、窗口秒数、使用百分比和重置时间。未知值保持 `null`，不会推断为零；读取不调用上游刷新、不计算宿主预测，也不更新订阅额度或账本。`host.quota_observations.refresh` 仍返回 unsupported。查询 JSON 必须放在 RPC payload 中，params 为 `{}`；查询最多 8 KiB，响应最多 1 MiB。回调绑定当前实例与 revision，停用或换代后不能继续读取。

## 实例自有资源

管理员触发的插件管理请求可调用 SDK `ensure_group` 和 `change_group_members`。每个实例最多登记 256 个分组资源，`resource_key` 最多 128 字节。同一实例及资源标识的并发或重复创建只产生一个分组；名称、描述和颜色只在首次创建生效，之后返回当前分组，不覆盖管理员修改。新分组使用现有默认预算和倍率，没有成员，也不会自动给普通用户分配权限。

成员修改一次最多增删 1000 个账号，不允许同一账号同时加入和移除；只改动本实例拥有的分组，保留账号在其他分组的关系。重复修改返回本次实际增删数量，缺失的新增账号会使整批回滚。写入、实例 revision 校验和审计在同一事务中完成，提交后发布正常运行时快照。

调用者身份由宿主从管理会话或管理 API Key 得到，保存在宿主调用上下文中，插件不能在正文中替换操作者。停用和换代阻止旧 revision 的新写入；已经取得事务锁的写入可先完成，然后停用生效。管理请求断开后，已开始的事务及快照发布继续收尾；超时或连接中断可能已经生效，应以同一 `resource_key` 重试查询或重复同一组增删操作，不能把超时当成未执行。

管理员删除分组后，资源登记保留删除标记，重复 ensure 会返回不存在，不会重新创建。卸载插件只删除资源登记，保留已创建分组及成员，管理员可以继续管理或自行删除。

SDK `ensure_key` 已开放，每个实例最多登记 256 个 Key 资源，只能由本人管理员会话调用；部署级管理 API Key 不能代替个人身份。Key 必须绑定恰好一个本实例分组，且该分组已启用并在本人权限范围内；不会自动给受限管理员新增分组权限。创建复用正常 Key 的随机密钥生成与事务鉴权，只返回 ID、名称、启用状态。Key 可在本人 Key 管理页查看，并用于页面推理。

预算是本地主程序与上游插件的重要差异：`daily_limit_usd` / `weekly_limit_usd` 在首次创建时必须等于本人该分组当前的有效共享额度，包含用户额度倍率。它们是校验值，不会通过创建 Key 修改分组额度或重置用量。不匹配时返回 conflict；应先由管理员显式配置分组额度及本人倍率，再使用匹配值。多个 Key 仍共享同一用户＋分组账本，没有独立插件额度。

同一实例和 Key 资源标识的重复创建返回原 Key，保留管理员后续对 Key 的修改；另一用户不能通过该标识取得或接管原 Key。Key 删除后保留删除标记，重试不会重建；卸载插件仅清理登记，保留真实 Key 和既有账本。共享额度写入使用下述本地扩展。

## 共享额度管理

本地 SDK 扩展 `call::shared_budgets` 提供三个 management 回调，方法以 `host.cpr.shared_budgets.v1.` 为前缀。它们需要当前管理调用及有效管理员身份；个人会话会在事务中重新检查用户启用状态和管理员角色，部署级管理 API Key 也可使用。管理员可以操作现有分组，不限于插件创建的资源。页面选择 Key 不会缩小这些管理权限。

| SDK 方法 | 输入及影响 |
| --- | --- |
| `shared_budget` | 显式 `user_id`＋`group_id`；返回配置 revision、分组基础限额、用户倍率、有效限额、保留窗口的用量和时间 |
| `update_shared_group_limits` | `group_id`、`expected_revision` 及至少一个日/周限额；修改该组所有用户的基础限额，保留各自倍率、历史用量、窗口及其他组属性 |
| `reset_shared_budgets` | UUIDv4 `event_id` 和 1～500 个明确的用户＋分组范围；重置选定订阅的日、周用量，复用现有订阅重置事务，保留账单流水 |

查询不会推进过期窗口，也不会刷新上游。尚无窗口时，用量为零、窗口时间为 null；客户端需要结合返回时间解释保留的窗口观测，不能把旧窗口用量当作当前可用余额。允许查询尚未创建 Key 的隐式全组管理员；重置范围必须已有用户分组授权或 Key 绑定，否则整批失败。

修改限额前先读取 revision；任意配置更新使旧 revision 失效并返回 conflict。查询后按当前值重新决定是否修改，不能在冲突后自动覆盖。`0` 沿用现有限额语义，表示该周期不限额。只返回基础限额，用户有效限额需要结合个人倍率，或重新读取 `shared_budget`。

重置会影响该用户在所选分组下的**所有 Key**。插件页面应明确展示影响范围并确认后提交。插件必须在发起重置前保存事件 ID；超时、断连或升级后继续使用同一个 ID 和同一组范围查询式重试，禁止换 ID 自动重试。范围会排序、去重；同一实例＋事件只记录一次重置与审计，改变范围返回 conflict。幂等记录保存在正常订阅重置表，版本切换不清除；已经取得事务锁的操作可先完成，再由停用生效。请求断开后提交和快照发布仍会收尾。

这是适配本地共享账本的扩展，不是上游 Key 预算接口的别名。上游 `host.keys.get_budget/update_budget_limits/reset_budget` 继续返回 unsupported；依赖 Key 独立额度的第三方插件需要调整其范围、界面及重试逻辑。它也不消费 OpenAI 上游重置卡。

## 外部认证

在声明 `frontend_authentication` v1 的实例配置中展开「外部认证」，启用客户端认证并填写外部身份到本地 Key ID 的 JSON 映射。该映射由宿主管理，不发送给插件；不是 Key 明文。每个实例允许 1～256 个映射，principal 最多 256 字节。同一时间只能启用一个入口认证器，数据库也约束这一点。仅安装认证插件而未设置此绑定时，仍使用普通 Key 认证。

认证覆盖 Responses JSON/SSE、WebSocket 握手、Images、Search 与模型目录。API 只传递一个有效的 `Authorization` 头，最多 8192 字节；不传递 Cookie、管理会话或其他请求头。插件在 5 秒内返回 `authenticated`、`not_matched` 或 `rejected`，其中 `authenticated` 只能包含外部 principal。宿主查询明确配置的 Key ID，再由 Core 检查当前启用状态和权限，使用该 Key 所属用户的分组、倍率、共享预算与正常结算。

默认策略为 `reject`。选择 `delegate` 后，仅插件明确返回 `not_matched` 才尝试普通 `sk_` Key；插件拒绝、返回未知身份或绑定 Key 无效返回 401，超时、崩溃、非法响应或恢复失败返回 503，不静默回退。普通 Key 回退保留原认证策略，不允许在密钥轮换过程中只凭旧 Key ID 获得新策略授权。

启用、停用、更换配置或版本会撤销旧入口授权，包括原本使用普通 Key 或回退认证的长连接；客户端需重新认证。失败升级保留旧认证器及旧授权，进程退出则撤销其授权。失败启动保留认证门禁，管理员可修复配置或停用后恢复普通 Key 入口。SSE 即使停止拉取正文，WebSocket 即使空闲，也会观察撤销；已产生费用按正常链路结算。

认证不改变管理登录。管理员会话、管理 API Key 和插件页面的本人选 Key 推理沿用原有权限入口，因此认证器出错时管理员仍可修复它。认证阶段仅允许当前实例的 `host.state.get/put/delete`，没有管理操作者身份，不能调用管理事实、资源创建或额度修改回调。

配置保存在迁移 `0030_plugin_frontend_authentication.sql` 增加的实例字段中，随完整 PostgreSQL 备份恢复。映射中的身份不会写入审计详情；插件必须自行避免输出认证信封和令牌。当前已验证真实 SDK 进程的认证调用与管理生命周期，以及 HTTP／WebSocket 的宿主映射和撤销；这不表示任意第三方认证插件的所有依赖回调均受支持。

## 限制与数据

单包最多 32 MiB；制品总量最多 128 个 / 512 MiB；最多 64 个实例。管理资源单个最多 1 MiB、注册资源合计最多 8 MiB；管理请求和响应正文最多 1 MiB。资源必须在清单和管理注册中声明，页面不得加载外部资源或嵌套 iframe，脚本须打包为普通脚本而非 ES module。

私有状态最多 16 个命名空间，每个最多 4096 条、4 MiB，单值最多 256 KiB，实际采用清单与宿主共同约束。版本切换不允许改变状态声明；需要迁移的插件版本当前不能原地升级。私有状态不能作为本地用户额度或账本的替代权威。

迁移 `0027_plugins.sql` 追加制品、实例与私有状态表，不修改已有迁移、用户归属或用户＋分组账本。完整 PostgreSQL 备份包含这些表；运行目录下的插件解包缓存可从数据库制品重建。恢复后仅启动已启用实例，单个插件启动失败不阻止网关启动。

## 后续改造边界

只读事实、实例自有分组/Key 和显式共享额度管理已接入；后续继续接入中间件和具体业务插件；原生进程模型回调与深度扩展仍未开放。现有差异功能尚未从主程序移出。用户、共享账本、请求结算和 Provider 凭据归属继续由核心模块负责。

本轮实际运行验证平台为 Linux x86_64。CLI 可生成 Linux x86_64 / aarch64、macOS aarch64 制品，但本轮未完成其他平台的真实进程验证，不提供 Windows 插件制品兼容保证。

### Responses HTTP 接入进度

request 挂载已接入 Responses JSON/SSE 的认证后链路：插件可改写协议正文，宿主重新校验模型和续接信息，并保留原 Key、请求 ID、截止时间及计费 owner。流式响应只有在整个首批改写结果有效且非空后才确认交付；原终态、费用和取消保持宿主所有。启用实例的撤销会中断正在等待上游的 SSE 并释放名额，响应改写失败不会抹掉已产生费用或自动重试上游。

这仍是分阶段接线：生产运行时继续拒绝启用 middleware，直到其余端点和传输等所声明范围完成验证。当前 HTTP 适配测试不代表任意第三方插件已兼容；非空计划的 JSON 总正文及 SSE 单批上限为 8 MiB，单批最多 1024 帧，无匹配中间件时沿用现有响应合同。


attempt 挂载已连接 Responses HTTP 和真实 SDK 子进程：每次重试独立调用，先校验并尝试登记原上游，再允许插件读取；费用、账号权限和续接状态由原执行链保留。插件可改写正文、客户端状态码和响应头，也可直接返回错误正文；改写不能改变已经冻结的模型、续接、storage intent、传输或能力需求。request 与 attempt 可同时挂载，仍只由原 Core 请求结算。

验证覆盖 JSON/SSE 透传、正文改写/展开、原始事实保留、错误短路、撤销与展开批次的交付屏障。非 2xx 错误正文可为原始字节，最多 8 MiB；JSON 来源最多保留 16384 个事件。这仍是生产启用前的接线验证，middleware 能力门禁保持关闭，尚不能直接启用任意第三方中间件。


### Images 与 standalone Search 接入进度

request/attempt 两层已接入 `/v1/images/generations`、`/v1/images/edits` 和 `/v1/alpha/search`，并通过真实 SDK 子进程的透传、事实读取、正文改写和错误短路测试。它们固定使用 OpenAI Provider 原生端点；图片生成/编辑类型由入口保持，正文中的模型不参与文本模型映射。插件输入与输出继续过滤受管身份头；attempt 仅重建原端点已有的 session、thread、turn metadata 和 image turn 请求头。

未改写的响应保留原始 JSON 字节、空白和字段次序，不包装成 Responses 对象。插件可修改客户端状态及正文，但不能修改原上游状态、费用和结算身份。请求取消、插件撤销、非法输出和超限均沿用同一 Core 清理路径。生产 middleware 门禁仍关闭，其余声明范围尚待接入；经过中间件的 JSON 文档仍受 8 MiB 上限约束，大图响应可能超限，无匹配中间件时保留原有大响应合同。


### WebSocket request/attempt 接入进度

Responses WebSocket 的 attempt 挂载已接入原 Core 执行与控制帧转发链。每个插件正文帧是一条完整 JSON 消息，不使用 SSE 字节；插件可改写消息内容或展开消息，宿主按整批校验后交付。原响应 ID、冻结模型、续接、stream 语义、连接 ID、上游传输标记与 Provider 私有状态保持原归属，避免把响应中断或下一轮续接指向其他执行。错误短路的 JSON 对象投影为带非 2xx status 的 WebSocket error 消息。

真实连接验证覆盖响应中断、错误 ID 拒绝、排队 create 串行执行、断连/撤销、原生续接状态和改写批次失败；SDK 子进程验证 JSON 消息透传、改写、展开及错误短路。等待 WebSocket 写入时仍检查插件撤销；Core 启动后、首次轮询转发前发生撤销也会释放并发并完成唯一结算。request 与 attempt 现已同时接通，共用同一根请求、交付屏障和费用 owner。生产 middleware 能力仍未开放，后续继续接入执行设置、嵌套宿主调用与其余声明范围。


request 插件获得不含 `response.create` 类型字段的请求 JSON，可以在正常 Core 权限与路由检查前改写模型和正文；客户端流式语义、连接身份、上游传输标记仍由入口保持。宿主按改写后的续接 ID 选择连接内私有状态，不从插件正文恢复状态。响应以完整 JSON 消息批次校验，不发送 SSE 的 `[DONE]`，只有通过校验才确认原交付；原始响应 ID 和费用不能被改写。

等待 request 插件、Core 启动及下一批响应时，复用原控制帧 pump，保持同一个读取 future，排队 create 仍串行执行。关闭连接、禁用插件或换代会中断等待并交还原清理 owner。request 层直接返回错误时不会启动 Core 或产生费用；attempt 层错误短路仍由已启动的 Core 请求收尾。容量不足的 503 与客户端续接重放错误复用原 WebSocket 投影，不被 request 插件链改成普通错误。真实连接覆盖三种挂载组合、next 前后挂起及改写续接后的私有状态隔离；真实 SDK 子进程与 Core 验证两层正文改写/展开、唯一交付确认和原始费用。


### Request 能力转换声明

Responses JSON/SSE/WS 的 request 层已接通 SDK `declare_capabilities`。声明必须与显式正文替换一起提交；`handled` 只能包含本层输入确实需要、替换后正文已不再需要的 tools、vision、reasoning、json_schema。重复项、空声明、handled/required 重叠、没有实际消除的功能都会被拒绝。转换后的响应还原由插件负责。

Core 路由仍校验改写后正文中的全部需求，并继承链入口中未声明处理的需求及各层额外 `required`。后层重新引入的功能会恢复检查，不能取消前层的额外上游要求；原生续接不能声明为已处理。attempt 重解码保留继承的声明，但继续独立比较实际正文的能力，不能在已选路由后借声明修改能力范围。声明仅用于 Responses request；attempt、Images 和 Search 会明确拒绝。

这项接线经过 SDK 子进程、嵌套 next 与本地 Core 路由验证，覆盖 HTTP JSON/SSE 和 WebSocket 两层组合。它不解除 middleware 生产启用门禁：请求级执行设置、宿主模型调用及其余声明范围仍在实施。


### 请求级运行设置基础

Core 已建立与持久化快照共用的 `SettingsValues`，覆盖本地已有的价格、模型映射、账号调度和最低客户端版本事实。`RequestSettings` 为每条调用分支保存宿主基线、有效快照及逐字段的插件来源/顺序；嵌套替换不修改父分支或其他请求，切换宿主基线时只继承显式改写，映射对象整体替换。

`PreparedRootExecution` 已能在原身份、权限、取消和期限下使用派生快照规划模型或固定 Provider 端点；不会重新认证、更新全局 revision 或建立另一个账本。基线不匹配和已撤销请求会被拒绝。此处仍是 Core 接入阶段：SDK `settings` 改写继续明确返回不支持，完整执行设置的 Fast 三态、客户端准入、可变期限及 RPC/attempt 视图尚待接线，不能据此认为上游设置插件已经可直接使用。
