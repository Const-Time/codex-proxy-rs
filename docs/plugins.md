# 插件安装与管理

管理员可在侧栏「插件」上传 `.tar.gz` 制品，创建实例、填写配置和敏感字段、启用或停用、切换版本、打开管理页面，以及卸载实例。普通用户不能安装或调用插件。

当前已接入 **B：协议与安装管理** 以及 **C：管理页面、私有状态与选 Key 推理**。SDK、CLI、包校验、RPC 和页面桥来自上游 v3.21.2 固定快照 `fb15f3e3`；本地 Admin、Store、API 和运行时接入保持现有职责划分。SDK 包含完整上游类型并不代表本地宿主已实现所有能力。

`command_line` v1 的注册、类型化参数、帮助、执行 RPC 与网关命令入口已接入。命令参数只进入二进制载荷，校验失败不执行命令，帮助隐藏敏感默认值；时长按有符号纳秒精确解析。执行使用原实例 revision、宿主操作者、冻结服务和同一调用图。本人命令按登录用户归属选择 Key；宿主系统命令可分页查询全部 Key 的 ID、名称和启用状态（每页 1–200 项），并按 ID 绑定原 Core 授权，不读取或返回明文密钥。系统权限只属于宿主签发的 command_line 根调用；管理页、管理 API Key 和插件 actor 不会获得该权限。模型推理仍走原权限、准入、额度、费用和实时撤销链；取消、超时或未确认响应不自动重跑，命令结束会关闭未读流和回调。Host 复用 Ctrl-C、SIGTERM 和原排空时限，等同一 Core 调用图完成结算与释放后停止 worker；清理超时会保留已确认结果并报告未完整完成。命令账号结果已接入下述原生校验和提交链；完整回调和目标制品兼容尚待验收，该能力仍不可启用。

只有宿主系统命令的零退出结果可以提交账号，每次最多 32 项，按顺序处理。SDK facts 是未验证输入：OpenAI 使用原凭据 codec 和导入/文件重新授权校验，从原生材料提取身份及有效期；xAI 使用原凭据解码及官方 OAuth 验证，有效期提示受原导入政策校验，刷新时使用官方响应的 token 生命周期。Provider 重建原生凭据与身份，不直接保存插件声明的套餐或刷新计划；替换必须匹配原账号身份和凭据 revision，不允许重绑身份。Admin 使用原导入/轮换事务、Provider 缓存失效和 Core 发布，Store 在同一事务内锁定实际启用的插件 revision，并记录插件审计身份；账号名称、启用状态和路由设置继续由原 owner 保存。

RPC 与账号处理共用命令总期限。准备开始后，原生账号任务保留同一 Core 调用图的 permit，继续完成事务和发布；命令等待取消不会丢弃已经准备的材料。后续项失败、取消或超时返回未完整完成，只报告已确认提交数，进行中的提交结果可能未确认，不自动重放。非零退出不提交账号，个人管理操作者不能使用该全局账号入口，错误不回显凭据。

账号回调请求和响应使用二进制 JSON 载荷，信封必须为 `{}`。`list` 支持 Provider 和游标过滤，每页 1–200 项；它与 `get_runtime` 只返回原生账号元数据。`get` 是显式敏感导出，会把原生 Provider 凭据材料交给插件，因此安装这类插件等于信任其处理账号凭据；材料不进入普通日志、Debug 或审计详情。`save` 与命令账号结果共用原 Provider 准备、导入或轮换事务、缓存失效及发布链，不接受插件声明替代原生身份和有效期。导入或 upsert 的回执直接携带提交事务返回的凭据版本，替换使用该版本进行原生 CAS，普通 HTTP 导入响应不变。

账号准备开始后，管理或维护 RPC 的等待者退出不会丢失提交的收尾责任。现有调用登记保留该次原生提交 permit 的只读完成句柄，结束的调用立即失去操作者和回调权限；句柄不持有 permit，也不等待同一父调用图中的其他工作。插件撤销阻止新提交，原 SDK 关闭流程确认回调 future 析构后，插件停止等待已开始的原生账号任务完成事务、缓存失效和发布。正常完成释放登记，仍在收尾的调用计入每实例最多 32 个调用作用域的容量，不另建凭据、任务或命令持久化状态。

授权使用宿主实际操作者与调用上下文。管理会话在原用户存储检查管理员角色和启用状态；普通用户、停用管理员、管理阶段的 System 或插件 actor 不能取得全局凭据权限。维护任务使用实际插件身份，终端回调要求真实 System 根调用。四类回调在原数据库事务中锁定实际启用的插件 revision，旧进程仍运行也不能越过停用或版本变更。保存从准备开始标记同一 Core 调用图的副作用，取消等待或超时后保留原生提交与排空责任，不自动重放。上游适配器绑定账号的凭据回调仍需接入实际 Provider 凭据持有与轮换合同，不能用这些全局回调替代；上述未开放能力仍保留门禁。

命令行沿用同一套配置、Bundle 和原插件发布，不另建命令索引。无参数仍启动服务；全局帮助不加载配置或连接数据库。实例帮助不执行命令，执行时由 Admin 解析当前启用版本并再次检查资格；参数错误不回显输入，非 UTF-8 输入不会回退到服务启动。实例命令仍受上述能力门禁约束。

```text
codex-proxy-rs --help
codex-proxy-rs plugin <实例 ID> --help
codex-proxy-rs plugin <实例 ID> <命令> --help
codex-proxy-rs plugin <实例 ID> <命令> [参数]
```

声明 `observer` v1、`observation` 阶段的制品可以启用观察订阅。实例字段 `observer` 为 null 或 `{order, requestCompleted, websocketResponse}`；两种事件分别选择全部请求、指定 Key 或分组，至少启用一种。顺序为 -10000～10000 的整数，指定范围最多 256 个唯一有效 ID；省略/null 清除绑定。订阅随原实例 revision、迁移 `0040_plugin_observer.sql` 及完整备份恢复，升级候选失败保留旧发布。管理页展示两种事件和独立作用范围，实际上游 WebSocket 原始响应可能包含请求的业务内容，应按所需范围授权。

Core 从同一份请求准备结果冻结订阅；Responses JSON/SSE/WS、Images、standalone Search 和原生模型子调用共用原计划，子调用排除全部发起插件祖先。终态只从原会话完成写入、费用结算和准入释放后的事实投影一次，未知费用保持 unknown 和空金额；不提供原始错误、凭据或诊断正文。实际上游 WebSocket 原始帧在中间件改写和重试丢弃前观察，序号跨 attempt 连续；客户端传输不会代替实际上游 transport。

原 Admin 发布共享编译一个 Runtime 计划：终态最多同时处理 16 个请求，WebSocket 最多 16 个请求队列、每队列 16 帧，原始载荷共用现有 RPC 缓冲预算并预留 16 KiB 元数据。原始 JSON 字节优先于重编码，重新编码前先检查字节上限；超限跳过观察事件，序号可能有间隔。单次观察 RPC 最多两秒。终态投递与帧队列独立，完成事件关闭帧队列，但不等待已入队帧处理完毕；插件按事件 ID 自行关联和去重，宿主不自动重投。

观察计划仍属于原发布 owner，使用独立观察撤销信号：订阅变更、停用、不可确认提交或宿主关闭撤销旧观察投递，不给模型请求增加业务取消源。观察进程恢复失败会跳过该订阅，不阻止其他观察实例或原模型目录；同时提供路由/中间件等业务能力的实例继续受原业务故障门禁约束。worker 对队列表仅持弱引用，实际匹配订阅者全部撤销会释放空闲队列。调用使用真实实例/revision、原请求关联、原调用图和冻结 service 发布；私有状态、外部 HTTP 与已授权 service 回调沿原作用域清理，显式缺失服务工厂不会读取后来发布。观察阶段尚不提供管理员会话或原生模型父执行；相应回调仍明确拒绝。


声明未支持能力的插件可保存为停用实例，但不能启用。未实现的宿主回调明确返回 unsupported，不伪造成功。宿主版本范围不匹配显示警告；包平台、摘要、协议或注册清单不匹配会拒绝启动。使用上游插件前须核对这张表；没有验证 workbench 或任意第三方插件的全功能兼容性。

中间件 v4 的单次 `next`、正文透传/改写、事实快照和取消已在 Runtime 内核通过 SDK 子进程验证。管理页可保存停用实例的中间件绑定：HTTP、WebSocket 会话、宿主服务、request/attempt 挂载和执行顺序。HTTP、WebSocket 会话和服务必须选择全部请求；request/attempt 可选择全部请求或指定 Key/分组。顺序较小者先进入，同序号按实例 ID 排序；响应按相反方向返回。分组匹配使用宿主冻结的 Key 授权分组，只选择调用范围，不增加资源权限。Responses JSON/SSE/WS、Images 和 Search 的 request/attempt 数据面挂载已接入验证；执行设置已接入 request 改写与 attempt 来源视图，原生模型子调用也已进入这两层计划。HTTP 的宿主惰性正文、冻结计划及 Runtime RPC 已接通真实 SDK；API 入口与原始 WebSocket 传输也已接入，HTTP、管理和 request/attempt 阶段的宿主主动分派已接入；独立 WebSocket 消息中间件已接入原生 Responses 和插件自有会话，service Runtime 执行桥与冻结计划已通过 SDK 验证，管理员 API Key 查询、生成、删除，以及本地设置和定价七项服务已接入；管理和已授权 service 层，以及原 Core 的 request/attempt、routing/scheduling/retry/upstream 阶段可主动调用这些业务；HTTP、独立 WebSocket、注册和认证阶段的主动调用也已接入；其他阶段继续实施。上表仍将 middleware 列为未开放；不能把合同或内核测试通过理解为第三方中间件现在可以直接启用。

绑定与实例共用 revision 和配置 CAS。候选升级准备失败仍使用旧代；无法确认配置是否提交时阻止继续使用旧绑定，重新保存确认后恢复。恢复失败的必需中间件保留作用范围内的门禁，进程退出也不自动跳过。启停、绑定和版本变更撤销旧调用计划，包含 RPC 已结束但正文尚未交付的响应。

## 通用外部 HTTP

SDK `HostClient.http` 使用宿主 `host.http.do_stream` 并按需读取；`host.http.do` 返回有限的完整正文。请求和响应保留二进制字节、插件显式请求头与 HTTP 状态，非 2xx 不自动转成 RPC 故障。SDK 字符串无法表示的响应头会返回 fault，并保留宿主已发送状态。它访问外部 HTTP(S) URL，内部路由仍使用既有 `host.http.dispatch` 及其冻结分派权限。

通用 HTTP 和上游专用 HTTP 共用一套受管正文资源；账号鉴权装饰只在上游专用入口执行。upstream 阶段的通用 HTTP 继承当前账号代理，并共用原发送水位；其他阶段不从插件传入的账号 ID 获取代理或凭据。请求/响应正文上限为 8 MiB，超过响应上限须流式读取；每调用最多 16 个 HTTP 流，单次读取 1–64 KiB，每个流只有一个读者。Host 的既有网络限制、响应总量和期限继续生效。

句柄不能跨调用或代次使用。RPC 结束、原调用取消、插件撤销/停用以及显式关闭会回收未读正文并唤醒挂起读取；SDK 取消一次读取等待后仍可继续同一次读取。请求、路由、选号、重试和 upstream 等已绑定 Core 的调用沿原调用图记录 HTTP 效果，不另建权限或账本。注册阶段也可使用通用 HTTP，但仍不获得私有状态写入、模型或管理能力；其他尚未实现的能力不会因该回调可用而自动开放。

## 模型目录

`model_catalog` v1 在 registration 阶段调用 `model_catalog.register`，以二进制 JSON 返回上游 SDK 的 `ModelCatalogRegistration`。注册有 5 秒上限、64 KiB 正文上限和每实例 256 个别名上限；注册阶段不提供模型、资源管理或状态写入权限；设置服务使用宿主签发的插件身份，不获得管理会话权限。

别名只能直接指向 `openai` 或 `xai` 已知目录中的真实模型。ID 必须全局唯一，不能与原生模型、设置映射的键或目标重名；目标不能是其他别名或设置映射的键。候选启用、升级和重启恢复先通过 Core 校验，失败升级保留旧进程和旧配置。

目录事实与中间件使用同一插件发布快照，不写入另一套模型配置。普通模型列表、Codex 目录、模型详情、Responses JSON/SSE/WS 和插件原生模型调用均使用这份目录；Codex 只改写别名标识，保留真实目标的完整原生字段。别名固定 Provider，不能扩大账号模型权限或凭空增加能力，费用仍由原 Core 根据真实调用结算一次。

每次请求在原 Key 快照上重新校验别名，并保留请求设置覆盖和授权撤销。宿主后续配置若与已发布别名冲突，该目录不可用；不会静默把别名改指到另一模型。可修改冲突设置或从保留的管理入口停用插件恢复。进程退出、停用、换代和提交状态未确认都会撤销旧目录及其在途调用；恢复失败保留门禁，查询期间撤销也不能返回旧结果。

## 受管上游适配器接入进度

Core 已建立请求内冻结的适配器选择计划，并传入原请求协调器和每次 Provider 尝试。公开请求模型与客户端传输类型来自 Core 的原请求记录，不能从可改写的正文推断。OpenAI、xAI 的 Generate 在原生 wire 解码之前选择适配器；原账号范围、选号、租约、凭据恢复、费用与失败反馈继续由宿主管理。Images、standalone Search 和独立 compaction 保留原生入口。

适配器入口由 Core 延迟到 ProviderStream 首次消费，确保先登记账号和 attempt；首次消费前撤销或到期不会调用适配器，丢弃未消费流会释放原账号租约。插件只能通过宿主连接端口使用选定凭据；费用固定使用路由选定的上游模型，本地 OpenAI 仍按实际返回档位优先、请求档位回退的规则计价。适配器计划撤销沿原请求取消和结算链传播。

Runtime 已在插件进程准备时执行 `upstream_adapter.register`：限制注册信封、适配器数量、唯一 ID、内置 Provider、认证类型、协议格式、模型和 Base URL/路径声明，失败候选不改变已有实例。Admin 读取注册事实用于后续绑定，不持有凭据或另一份执行配置。路径声明标记推理与辅助请求的用途；它不是出站地址白名单，运行时目标仍按 SDK 合同解析相对或完整 HTTP(S) 地址。

Host 已提供受管 HTTP/WebSocket 传输：DNS 固定、代理与 TLS 校验、禁止重定向和代理失败后直连、有限容量、分块读取、期限及连接回收。HTTP/2 使用正确的 authority，避免额外 Host；WebSocket 支持并行收发、握手拒绝正文和关闭唤醒。该传输保留宿主观测到的未发送/已发送/不确定状态，不接受插件自报发送状态。

Core 的不透明会话状态可携带宿主记录的插件实例、贡献、适配器、代次和进程身份；连接内续接保持 ConnectionLocal 范围。缺少适配器时，OpenAI/xAI 原生执行和 xAI 独立 compaction 拒绝解释插件私有状态，明确要求客户端重放。SDK 中间件能读取归属事实，但改写或丢弃其副本不能删除宿主状态；原有无扩展归属的 Provider 会话继续使用原序列化合同。

Runtime 已接通真实 SDK 子进程的适配调用、受管 HTTP/流读取和 WebSocket 回调。每个调用的网络资源绑定原请求、attempt、选定账号及凭据版本；停止调用立即回收正文资源。凭据由 Host 连接注入，插件请求载荷不包含宿主凭据。HTTP 流按需读取，单次读取最多 64 KiB；WebSocket 允许读取等待期间发送消息，SDK 取消等待后继续同一次读取。发送状态只采用 Host 观测，在途发送取消按不确定处理，插件自报状态不能降低宿主水位。

upstream 阶段的私有状态、普通/流式模型调用，以及 `host.http.dispatch` 和正文资源回调已绑定同一在途调用。模型与内部 HTTP 使用原 Core 父调用、冻结的权限/配置和共享调用图，不从插件传入的 ID 构造权限；子模型避开发起祖先插件及父调用占用的账号，各次真实执行由原账本分别结算。内部 HTTP 使用父请求冻结的分派入口；其效果和已发生的子模型效果禁止父请求透明重放。终态、取消、撤权和停用统一回收模型流与 HTTP 资源，未读取的子模型流保持冷执行。私有状态继续校验当前实例、revision、命名空间、schema 和 CAS；本阶段不持有管理请求的操作者权限。通用外部 HTTP 也已绑定该调用：继承选定账号的代理，但仅发送插件显式提供的业务请求头，不注入账号凭据；与上游专用 HTTP/WS 共用宿主发送水位，发送或不确定发送后收紧原 Core 的重放判断。upstream 的主动 service 已沿原 Core 上下文接入；其余回调继续实施，生产适配器门禁保留。

事件解析验证协议、事实序列和响应身份，拒绝插件伪造宿主事实。费用经原选定账号的定价端口计算，采用实际返回档位。成功终态必须等 RPC 正常结束后才交付；尾部故障保留已解析计量事实，但不会交付成功终态。当前支持 JSON、原始 JSON 和 SSE 事件，原始 HTTP body 事件仍待接通。

续接同时核对插件实例、贡献、适配器、代次、进程、Key、账号与凭据版本；连接内续接从同代连接池独占领取。只有正常完成后才保留连接，空闲连接不持有账号租约，插件撤销关闭保留连接。每个适配器最多保留 64 个空闲连接，最长 30 分钟。

实例字段 `upstreamAdapter` 保存宿主作用范围，可选全部请求或指定 Key/分组，随迁移 `0038_plugin_upstream_adapter.sql` 和原实例 revision 备份恢复。一个绑定覆盖该实例注册的全部适配器，按内置 Provider 与公开请求模型匹配；注册模型列表为空时沿用绑定范围。同一实例或不同实例的 Provider、公开模型和作用范围重叠时，候选发布失败并保留旧版本；Key 范围与分组范围无法证明互斥，因此按可能重叠处理。

正常 JSON/SSE/WS 和原生模型调用入口将同一管理发布快照传入 Core。匹配依据宿主冻结的 Key、分组及公开模型，排除全部发起插件祖先；匹配但未恢复的实例保留拒绝门禁，不能悄悄走原生执行。成功选中的进程撤销加入同一请求取消链；停用、配置替换或保存结果不确定时撤销旧发布。未匹配的进程撤销不加入当前请求。

执行回归使用真实 SDK 子进程和本地 HTTP/WebSocket 服务；管理发布回归使用真实 SDK 候选进程，测试专用 Runtime 仅绕过生产启用门禁。真实 Core、原生 OpenAI/xAI Provider、PostgreSQL/Redis 账号协调与 SDK 子进程的 HTTP 回归已验证冻结分组权限、各 Provider 的受管认证头、实际档位和本地定价倍率、唯一费用结算、尾部故障禁止重放，以及用户取消、Key 撤权和插件停用后的原租约释放。xAI 使用原凭据仓库、选择器、额度投影及失败反馈，外部网络端口由测试替换；已解析的上游限流进入原账号冷却，插件 RPC 故障不降低账号资格。两家 Provider 的持久化续接均通过原 Redis 仓库恢复：同 Key/账号及插件代次可继续，另一有效 Key 在准入前拒绝；升级后旧状态在出站前拒绝，新请求仍可正常执行。执行记录和费用由原测试端口观测，不能将这些回归等同于完整 PostgreSQL 账本验收。Core 观测端推进混合 canonical/wire 帧中的序列事实，防止漏记开始或完成；wire 帧仍不受旁路事实的交付门禁约束。Core 的 WebSocket 客户端传输元数据、两家原生 Provider、SDK 与 Host 受管 WS 已联合验证同连接多轮续接、取消读取后恢复、唯一结算，以及取消/撤权/停用关闭在途和空闲连接。插件进程重启及原凭据 CAS 推进版本后，旧状态在出站前返回 `previous_response_not_found` 并要求客户端用完整输入重建；同一旧连接的并发领取只有一方成功，失败方不关闭胜出请求保留的连接。实例、Key、账号、凭据版本和进程归属不符均采用明确的客户端重放语义，Core 不对此内部重放。完整 API 客户端 WS、PostgreSQL 账本、upstream 阶段其他宿主回调、原始 HTTP body 事件及第三方插件兼容继续验收；`upstream_adapter` 生产启用门禁保留，当前管理页面可保存停用实例的绑定。

## HTTP 运行时桥接

HTTP v4 内核保留原始 method、URI、版本、多值头、数据帧、trailers 和宿主 extensions。请求正文在插件读取时才推进；透传直接返还原正文，部分读取后继续传递未读部分。插件改写上传时使用单缓冲管道，终端提前返回即关闭写入，不预先收集完整正文。每次调用最多保留 32 个正文资源、16 个上传管道；跨调用或已经消费的句柄不能复用。

正文流和升级会话继续持有原 RPC 范围，直到流结束、会话完成、取消或到期。停用、换代和进程退出会撤销已经取得初始回复的输出。插件不能吞掉宿主终端或正文的原始错误，也不能在 HTTP 范围签发模型、管理或资源权限；没有宿主设置基线时不能自行构造设置。

升级任务只接受宿主产生的同一握手响应句柄及原状态，成功交付后单次领取；修改握手或丢弃响应不会启动会话。非法状态、伪造来源和未知帧标签让插件进程进入故障状态，显式重启后恢复。主动业务拒绝仍可处理后续请求。以上 Runtime 行为已通过真实 SDK 子进程验证，API 入口和原始升级传输已接入本地 Router/发布计划/Core 账本验证。HTTP、管理和 request/attempt 阶段的宿主主动分派，以及独立 WebSocket 消息挂载均已接入；service 挂载继续实施，生产 middleware 门禁继续保留。

## HTTP API 接入

HTTP 计划位于路由匹配之前，可改写 method、URI 或头，再进入同一个 Router。短路和零终端超时在认证/解码/Core 准入之前返回，不创建模型费用。最终模型请求仍通过正常 Key 或外部认证入口；HTTP 上下文没有 Key/管理员执行权限。运行设置在正常鉴权后 rebase 到该 Key 的冻结快照，再建立该 Key 的执行默认值；request/attempt 层复用同一插件发布计划及撤销链，覆盖值和逐字段来源继续保留。

原始字节与 trailers 仍惰性传递。HTTP 撤销在 next 前、next 后等待、缓冲 JSON 交付和挂起 SSE 中均生效，原 Core 只完成一次结算和槽位释放。API 终端超时沿入口开始时间计算，保留 408 状态；它是等待响应头的预算，不给响应正文附加总超时。

HTTP 层可领取 API 提供的原始 WebSocket 升级能力，保留验证后的协议与二进制消息。会话读取队列只有一个缓冲槽位，独立读写锁避免收发相互阻塞。成功握手保留 Host 连接登记至会话结束；修改或丢弃握手不启动会话，也不等待传输升级才释放名额。原生 Responses WebSocket 经过 HTTP 层时使用同一握手任务保护，并沿原 create/权限/控制帧/费用链执行。插件停用、Host 排空、对端关闭会及时收敛连接；没有模型调用的自有会话不产生模型费用。

新增 20 项本地 API 合同测试，总计 423 项 API 测试通过，覆盖正常鉴权、method/URI 重新匹配、两层设置来源继承、唯一计费、JSON/SSE 撤销及真实 TCP 的原生/自有会话与握手丢弃。该证据与 Runtime 的真实 SDK 测试分别验证各自边界；完整第三方插件端到端验收仍待完成。`host.http.dispatch` 已接通 HTTP、管理和 request/attempt 阶段，独立 WebSocket 消息中间件已接通，service 中间件以及 upstream_adapter 继续实施，生产启用门禁继续保留。

## Service 运行时桥接

`service` v4 的 Runtime RPC 与 Admin 冻结计划已接通真实 SDK 子进程。调用携带宿主 operation、request/call/parent ID，JSON 输入输出和 `Result` 错误合同不借用 HTTP 正文句柄。每次 `next` 只能领取一次；带意外二进制正文的 next 请求在领取前拒绝。插件按绑定顺序进入，响应逆序返回，祖先排除使用同一 Core 调用图。

空计划直接使用原生输入输出，不做 JSON 往返。Admin 的类型化边界在调用原服务之前反序列化改写输入，在返回原调用者之前校验输出类型。原终端继续负责授权、字段校验和事务；中间件上下文不签发管理或模型身份。业务错误保留 kind/message/details，可通过 SDK 的类型化 Result 处理；RPC 拒绝保留原 PluginFault 详情及 ambiguous 发送事实，不把不确定结果伪装成未执行；非法 RPC 回复或意外二进制结果隔离当前进程代次。停用、换代、父取消及期限会撤销等待，旧计划不会自动切换到新进程。

管理 HTTP 已接通 `settings.admin_api_key_exists`、`settings.regenerate_admin_api_key`、`settings.delete_admin_api_key` 三项实际服务，输入输出与对应上游 SDK 合同一致。调用沿用 HTTP 冻结发布和原调用图，使用管理审计边界签发的 request ID；服务入口在原管理员鉴权之后。原生终端拒绝改写 actor/request ID，生成与删除仍由原 SettingsService 持久化并发布配置。Key 明文只在显式生成结果中编码，不赋予领域 Key 通用序列化能力。

服务写入开始后，原事务和发布不随插件等待者一起丢弃，也不自动重试；同一调用图的名额保留到原写入与配置发布结束，沿原副作用标记阻止祖先重放。插件随后失败、撤销，或在写入尚未完成时提前返回成功，管理 API 返回原 `502 / 50202` 不确定结果合同；原终端失败不能被插件伪装成成功。查询允许按 service 合同短路和改写结果，恢复入口仍可用。

管理调用和已有授权的 service 层可以使用原 SDK `host.service<Operation>(input)`，通过 `host.services.call` 主动调用这些服务。管理入口仍要求管理员鉴权；服务端口、冻结发布、请求关联、调用图及取消信号由宿主绑定，不从插件 JSON 反序列化。请求里的 SDK MutationContext 会在边界被替换为真实管理操作者和审计 request ID，再进入 service 中间件；后续层不能修改这些身份字段。未绑定授权的调用、意外二进制正文和多余字段被拒绝，未知操作返回 unsupported。

服务子调用排除发起实例及全部祖先，与模型和 HTTP 子调用共用原 Core 的深度、活跃名额和总次数限制。管理 RPC 的模型及 HTTP 回调也继承原入口调用图和冻结 HTTP 端口，不创建第二个预算或读取后来替换的全局端口。RPC 结束、父请求取消、停用和换代撤销旧端口；等待中的服务回调取消时保留 ambiguous 结果，不自动重试。原生写入仍按前述规则持有图名额至事务和发布完成。

Admin 已提供宿主签发的插件服务身份端口，写入审计使用 `plugin:<实例>@<revision>`，与管理员会话、管理 API Key 和系统任务分开。该身份只绑定原插件代次及其撤销信号，不能作为管理端登录身份，也不自动获得本地共享额度或用户管理权限；服务输入中的操作者仍由宿主覆盖。Core 模型及策略调用携带与原请求计划相同的冻结服务发布；原生子调用继承父端口，不重新读取全局服务发布。Runtime 已将 request/attempt、routing/scheduling/retry/upstream 的真实在途调用绑定到这个端口，核对原实例、代次及完整 CallContext，并沿原图、期限和取消链清理。嵌套 service 层重新绑定实际执行插件；源自已鉴权管理调用的原操作者保持不变。HTTP 和独立 WebSocket 沿入口冻结端口绑定；注册及无 HTTP 父入口的认证在原 RPC 开始前冻结当前服务发布，实际 HTTP 认证保留入口上下文。显式缺失服务端口不会回退到全局端口。独立 WebSocket 消息各有调用预算；从模型或内部 HTTP 子调用建立的连接继承父图、祖先和累计预算。取消、期限及 RPC 结束关闭当前消息或注册/认证的服务范围。其余阶段继续实施。各阶段的端口回归不等同于完整 API 与第三方原包的端到端兼容。公共 settings 的操作者 DTO 保持上游三类合同：管理员会话、管理 API Key 和 System。插件主动调用在该 DTO 中表示为宿主系统调用，真实插件身份和 request ID 由终端单独持有，数据库仍记录 plugin 实例及 revision；中间件改写传输操作者或 request ID 会在写入前拒绝。显式 local.settings.v1 使用独立 MutationContext，保留 Plugin 操作者事实。固定 b37d7901 原 SDK 的独立进程已通过真实 PostgreSQL 的生成、删除、两次配置发布和审计核验，覆盖类型化 service 中间件及改写拒绝；这是三项公共操作的证据，完整第三方原包兼容仍须逐项验收。

本地运行设置和定价使用 SDK `call::services::local_settings_v1`，操作前缀为 `local.settings.v1.`。管理页对应接口也经过这些服务层，HTTP 响应格式保持原合同。下列写操作的输入均以 `(MutationContext, command)` 传递，宿主绑定真实审计身份；模型映射、版本、价格与源预览仍由原 Admin/Store 用例校验和发布。

服务结果在交付前完成类型和领域转换；写入后插件破坏响应或中途取消，返回原不确定结果合同，不能把提交事实变成一次可安全重试的失败。自动定价刷新仍由原后台 owner 执行，不因页面读取或插件加载而触发。

上游 `settings.load/replace` 等完整设置接口仍明确返回 unsupported：本地没有 Guardian、预热和客户端画像等字段，不填造默认值，也不把本地类型放到同名上游接口。管理员 API Key 的三个公共操作继续使用原上游合同。HTTP、独立 WebSocket、注册、认证与原 Core 执行/策略阶段的主动服务已绑定宿主原上下文；其余阶段继续验收。生产 middleware 启用限制继续保留。

## 插件故障恢复

宿主保留一组不经过 HTTP 插件的恢复入口：管理员登录、会话状态、退出，以及插件实例列表/创建、制品列表/上传/删除、配置更新和卸载。它们仍进入原 Router 的鉴权、审计、revision 校验与管理用例；未登录和普通用户不能借此修改插件。即使插件拒绝所有请求、一直等待或已故障，管理员也可以停用它，停用响应不会被刚撤销的插件取消。

浏览器可从 `/`、`/login` 或 `/plugins` 进入恢复操作；这些页面的 GET/HEAD、`/assets/` 下的静态文件与 `/favicon.svg` 也由宿主直接提供。不要把这些固定入口用于自定义 HTTP 插件路由。插件页面资源、invoke、页面模型推理，以及其他业务和管理接口仍经过原插件计划，故障时不会自动放行。路径必须精确匹配，类似前缀不会获得豁免。

内部 `host.http.dispatch` 访问恢复接口同样需要显式凭据；宿主不注入管理会话。其响应保留原调用图名额至正文消费或丢弃，并继续受原取消和期限约束。恢复操作使用原实例配置和存储提交，没有第二套开关或恢复数据库。

## WebSocket 消息中间件

独立 `websocket` 挂载在连接建立时冻结实例、顺序、祖先排除与撤销源。入站消息先进入插件，再由原生 Responses 协议解析；出站消息经过同一层，再写入原传输。插件自有升级会话也复用这一消息链。Text、Binary、Ping、Pong 和 Close 保留原始载荷；`next` 单次使用，返回 null 可丢弃消息，直接发送写入原连接而不会再次进入自身中间件。

每次消息 RPC 拥有独立的惰性载荷句柄，透传不需要把大消息塞入 RPC payload。部分读取后只转交未读部分；句柄不能跨调用或重复消费，每次调用最多保留 16 个载荷。正文和 `next` 之外不授予模型或管理身份。非法回复或伪造句柄使该代次故障，显式重启可恢复；插件不能吞掉或替换原终端、发送端的首个错误。

API 保留原生连接循环、控制帧处理、发送确认和连接寿命预算。消息变换期间不持有传输写锁，插件可主动发送；接收使用单槽队列施加背压。正常 Key 鉴权先于原生升级，原 Core 仍唯一拥有准入、上游费用、倍率和结算。插件停用会关闭闲置、等待中和活动连接，丢弃消息或主动发送本身不创建模型账单。

真实 SDK 子进程与真实 TCP/Router/Core 回归覆盖消息类型、大载荷、改写、丢弃、直接发送、控制帧、唯一计费、故障恢复及撤销。本地 `service` 和 `upstream_adapter` 等剩余合同及第三方插件验收尚未完成，middleware 生产启用门禁仍保留。

## 宿主 HTTP 主动调用

原生 request/attempt 调用携带宿主签发的父模型上下文，保留父请求历史关联、执行期限、全部活动祖先账号和实时撤销。HTTP 和模型调用使用同一调用图；采用已有 HTTP 名额时不会再次预留模型名额。目标接口仍按显式凭据鉴权，换 Key 不继承原 Key 的 Fast、并发和 RPM 覆盖。内部分派的副作用阻止祖先重放，但不阻止子请求自身满足原规则的安全重试。管理调用继续使用原管理 RPC 作用域；不会把原会话自动注入 HTTP 请求或合成管理员身份。

组合根持有 API 分派端口，Runtime 仅保存弱引用；原生父请求可以持有其冻结端口，作用域结束即释放。管理、request 和 attempt 复用原 HTTP 惰性资源池，调用结束或插件停用会撤销读取和等待中的分派。分派开始后失败或丢失回复不能证明操作尚未执行，错误保留 ambiguous 结果，不作为安全重放依据。

HTTP、管理和 request/attempt 阶段已接通 SDK `HostClient::dispatch_http`，只接收宿主相对路径，method、URI、多值头、原始字节和 trailers 使用同一个 HTTP 资源池。子调用进入原 Router，由目标接口正常鉴权；它不会自动取得原请求的 Key 或管理员权限。插件须显式提供目标接口要求的凭据。认证、路由、调度和重试等策略阶段仍遵守各自的回调权限，不开放内部 HTTP。

父调用 ID、调用图和实例祖先由宿主签发。发起实例及所有祖先不会再次进入 HTTP/request/attempt 链；HTTP 子请求沿同一发布快照和设置来源执行；原生父执行持有冻结的 HTTP 端口，后续插件发布不会替换其内部调用计划。管理调用在内部 HTTP 入口获取发布快照。调用图与模型子调用共用 8 层深度、16 个活跃子调用和 64 次总调用限制，释放正文不会重置总预算。已经完成模型结算但尚未消费的 HTTP 响应仍占用调用名额；名额在响应结束或被丢弃、且原 Core 清理完成后回收。父调用撤销会中断子请求和 SSE，原子请求只结算一次。

内部 HTTP 可能在模型发出之前修改宿主状态，因此分派会记录到 Core 原有副作用标记，阻止父模型请求自动重放这些效果。插件可以处理独立子调用及其正文错误；原 next、原始请求正文和原响应正文的错误保护保持原合同。API 的真实 Router/Core 回归与 Runtime 的真实 SDK 子进程回归分别覆盖权限、祖先排除、名额寿命、取消、原费用、原始字节、trailers 和总调用预算。完整第三方插件端到端兼容验收仍待完成，生产 middleware/upstream_adapter 门禁继续保留。

## 模型路由

声明 `model_router` v1、支持 `routing` 阶段的实例可启用「模型路由」绑定。配置包括顺序（-10000～10000）、全部请求或指定 Key/分组，以及故障策略。范围与中间件共用冻结的 Key 授权分组，只决定何时调用插件。绑定保存在实例的 `modelRouter` 字段中，与配置、启停和升级共用 revision；没有独立的插件路由配置库。

宿主在请求正文适配完成、Core 准入之前按顺序和实例 ID 调用 `policy.route_model`。插件收到原公开模型、协议正文、过滤后的请求头，以及当前授权账号范围内已注册的 Provider。`unhandled` 交给后续策略；首个 `route` 选择公开模型和/或 Provider，至少提供一个；`reject` 明确拒绝请求。故障策略 `reject` 在超时、崩溃、非法响应或恢复失败时拒绝；只有显式配置 `delegate` 才跳过故障策略继续执行。显式 `reject` 始终拒绝，不因故障委托而回退。

Core 再次校验目标 Provider、模型能力、原请求输出上限与私有续接归属，不允许路由扩大 Key/分组权限或改写宿主凭据。历史记录保留客户端请求的模型，各次尝试记录实际上游模型。Responses JSON/SSE/WS 和原生模型调用使用同一策略；Images/Search 继续使用其固定 Provider 路由。

`routing` 阶段只开放实例私有状态和原生模型回调，模型调用继承宿主签发的父执行权限、期限、取消与设置；从子请求策略中排除全部发起祖先。真实子调用仍独立准入、计费和结算；子调用已发送后，父请求不能自动跨 Provider 重放。该阶段没有管理操作者身份，不能查询管理事实、创建资源或修改共享额度。启停、绑定或版本变化撤销原策略及已返回路由决定的在途执行；升级准备失败保留旧代。

## 安装、升级与恢复

1. 使用匹配宿主 OS/架构的二进制，通过 [CLI](../backend/apps/plugin-cli/README.md) 打包。
2. 上传并选择制品，填写 JSON 配置；清单声明的敏感字段必须使用独立密码输入框，不能放进普通 JSON。
3. 确认信任该插件及版本后启用。插件采用 `trustedProcess`：以网关系统身份运行，能够访问主机文件、凭据与网络，不是代码沙箱。
4. 切换版本时，候选进程先完成握手和注册，再提交数据库并撤销旧版本入口；候选准备失败保留旧实例。实例 revision 失效后需刷新页面。
5. 停用保留配置和私有状态；卸载要求已停用，并删除该实例及其私有状态。制品单独保留，可在「已上传制品」删除没有实例使用的版本。

单个进程崩溃不会阻止其他实例运行，页面会显示不可用；当前没有自动重启循环，管理员可以重新保存并启用。数据库提交回复丢失时，服务端读取权威记录确认结果；不能确认时停止相关实例，管理员刷新后重新启用，不自动重复插件业务调用。

敏感字段不出现在列表、审计详情或普通日志；留空保留，勾选清除后删除。敏感值保存在 PostgreSQL，未增加独立加密层，数据库备份同样包含敏感配置。不要把凭据填入清单未声明为 secret 的普通配置字段。

## 页面推理

打开插件页面后，点击「查询 Key」并显式选择本人启用的 Key；最多显示匹配的前 100 个，可按名称搜索缩小范围。未选择时管理页面仍可用，模型调用会被拒绝。更换 Key 会重新加载插件页面；关闭页面、切换插件实例或版本会取消该页面的请求，新实例需要重新选择 Key。

页面通过 `window.codexProxyPlugin.models.responses({clientKeyId, body, signal})` 获得标准 `Response`。`body` 是 Responses JSON 对象，`signal` 用于取消。本地宿主额外提供只读 `models.clientKeyId`，仅含所选 ID；父页面拒绝其他 ID。Key 明文由服务端按本人归属解析，只在服务端进入普通 Responses 链路，不传给 iframe 或原生插件。部署级管理 API Key 不能代替个人会话。

插件停用、进程退出或 revision 更换会撤销正在进行的页面推理。Key、用户或账号范围权限变化发布到运行时快照时，同样撤销调用；停用后重新启用不会恢复旧调用。权限比较采用整个 Key 策略，因此其他改变该策略的更新也可能中断调用。已冻结的计费事实不随撤销改写，已取得费用仍按现有链路结算。

每页最多 4 个并发模型调用、正文最多 8 MiB，最长 10 分钟；流采用逐块拉取，每块最多 64 KiB，等待下一次读取或数据超过 30 秒则取消。服务端在页面停止拉取时仍监听撤销，并释放 Core 执行资源。流被取消后不会自动重试。

可运行示例：[推理便笺](../backend/crates/gateway-plugin/sdk/examples/prompt-pad/README.md)。它只声明 management v1，支持发送、流式显示和停止；内容仅保留在页面。已验证 Linux x86_64 的 SDK 构建、CLI 打包、真实进程握手与注册，以及浏览器页面桥对本地 SSE 测试响应的读取和取消；未使用生产账号产生真实模型费用。

## 插件读取宿主事实

可信插件的管理请求可通过 SDK `key_facts`、`account_facts`、`quota_facts` 查询现有数据。这些接口属于管理员安装的全局管理能力，不受页面所选 Key 限定；普通用户没有管理入口，也不会获得这些回调权限。页面选 Key 仍只用于本人模型推理，不能授权账户管理。

Key 查询只返回 ID、启用状态和显式分组绑定；账户查询只返回 ID、Provider、名称、邮箱、分组、启用状态及更新时间。账户列表按 ID 升序分页，`limit` 为 1～100，可按 `openai` / `xai` 筛选，继续查询时传入上一页 `next_cursor`；末页为 `null`。空分组表示没有显式绑定，不代表全账户权限。

额度查询只读取 Provider 已有观测，返回观测时间、窗口标识、窗口秒数、使用百分比和重置时间。未知值保持 `null`，不会推断为零；读取不调用上游刷新、不计算宿主预测，也不更新订阅额度或账本。`host.quota_observations.refresh` 仍返回 unsupported。查询 JSON 必须放在 RPC payload 中，params 为 `{}`；查询最多 8 KiB，响应最多 1 MiB。回调绑定当前实例与 revision，停用或换代后不能继续读取。

## 实例自有资源

管理员触发的插件管理请求可调用 SDK `ensure_group` 和 `change_group_members`。每个实例最多登记 256 个分组资源，`resource_key` 最多 128 字节。同一实例及资源标识的并发或重复创建只产生一个分组；名称、描述和颜色只在首次创建生效，之后返回当前分组，不覆盖管理员修改。新分组使用现有默认预算和倍率，没有成员，也不会自动给普通用户分配权限。

成员修改一次最多增删 1000 个账号，不允许同一账号同时加入和移除；只改动本实例拥有的分组，保留账号在其他分组的关系。重复修改返回本次实际增删数量，缺失的新增账号会使整批回滚。写入、实例 revision 校验和审计在同一事务中完成，提交后发布正常运行时快照。

调用者身份由宿主从管理会话或管理 API Key 得到，保存在宿主调用上下文中，插件不能在正文中替换操作者。停用和换代阻止旧 revision 的新写入；已经取得事务锁的写入可先完成，然后停用生效。管理请求断开后，已开始的事务及快照发布继续收尾；超时或连接中断可能已经生效，应以同一 `resource_key` 重试查询或重复同一组增删操作，不能把超时当成未执行。

管理员删除分组后，资源登记保留删除标记，重复 ensure 会返回不存在，不会重新创建。卸载插件只删除资源登记，保留已创建分组及成员，管理员可以继续管理或自行删除。

SDK `ensure_key` 已开放，每个实例最多登记 256 个 Key 资源，只能由本人管理员会话调用；部署级管理 API Key 不能代替个人身份。Key 必须绑定恰好一个本实例分组，且该分组已启用并在本人权限范围内；不会自动给受限管理员新增分组权限。创建复用正常 Key 的随机密钥生成与事务鉴权，只返回 ID、名称、启用状态。Key 可在本人 Key 管理页查看，并用于页面推理。

预算是本地主程序与上游插件的重要差异：`daily_limit_usd` / `weekly_limit_usd` 在首次创建时必须等于本人该分组当前的有效共享额度，包含用户额度倍率。它们是校验值，不会通过创建 Key 修改分组额度或重置用量。不匹配时返回 conflict；应先由管理员显式配置分组额度及本人倍率，再使用匹配值。多个 Key 仍共享同一用户＋分组账本，没有独立插件额度。

同一实例和 Key 资源标识的重复创建返回原 Key，保留管理员后续对 Key 的修改；另一用户不能通过该标识取得或接管原 Key。Key 删除后保留删除标记，重试不会重建；卸载插件仅清理登记，保留真实 Key 和既有账本。共享额度写入使用下述本地扩展。

## 共享额度管理

本地 SDK 扩展 `call::shared_budgets` 提供三个 management 回调，方法以 `host.cpr.shared_budgets.v1.` 为前缀。它们需要当前管理调用及有效管理员身份；个人会话会在事务中重新检查用户启用状态和管理员角色，部署级管理 API Key 也可使用。管理员可以操作现有分组，不限于插件创建的资源。页面选择 Key 不会缩小这些管理权限。

| SDK 方法 | 输入及影响 |
| --- | --- |
| `shared_budget` | 显式 `user_id`＋`group_id`；返回配置 revision、分组基础限额、用户倍率、有效限额、保留窗口的用量和时间 |
| `update_shared_group_limits` | `group_id`、`expected_revision` 及至少一个日/周限额；修改该组所有用户的基础限额，保留各自倍率、历史用量、窗口及其他组属性 |
| `reset_shared_budgets` | UUIDv4 `event_id` 和 1～500 个明确的用户＋分组范围；重置选定订阅的日、周用量，复用现有订阅重置事务，保留账单流水 |

查询不会推进过期窗口，也不会刷新上游。尚无窗口时，用量为零、窗口时间为 null；客户端需要结合返回时间解释保留的窗口观测，不能把旧窗口用量当作当前可用余额。允许查询尚未创建 Key 的隐式全组管理员；重置范围必须已有用户分组授权或 Key 绑定，否则整批失败。

修改限额前先读取 revision；任意配置更新使旧 revision 失效并返回 conflict。查询后按当前值重新决定是否修改，不能在冲突后自动覆盖。`0` 沿用现有限额语义，表示该周期不限额。只返回基础限额，用户有效限额需要结合个人倍率，或重新读取 `shared_budget`。

重置会影响该用户在所选分组下的**所有 Key**。插件页面应明确展示影响范围并确认后提交。插件必须在发起重置前保存事件 ID；超时、断连或升级后继续使用同一个 ID 和同一组范围查询式重试，禁止换 ID 自动重试。范围会排序、去重；同一实例＋事件只记录一次重置与审计，改变范围返回 conflict。幂等记录保存在正常订阅重置表，版本切换不清除；已经取得事务锁的操作可先完成，再由停用生效。请求断开后提交和快照发布仍会收尾。

这是适配本地共享账本的扩展，不是上游 Key 预算接口的别名。上游 `host.keys.get_budget/update_budget_limits/reset_budget` 继续返回 unsupported；依赖 Key 独立额度的第三方插件需要调整其范围、界面及重试逻辑。它也不消费 OpenAI 上游重置卡。

## 外部认证

在声明 `frontend_authentication` v1 的实例配置中展开「外部认证」，启用客户端认证并填写外部身份到本地 Key ID 的 JSON 映射。该映射由宿主管理，不发送给插件；不是 Key 明文。每个实例允许 1～256 个映射，principal 最多 256 字节。同一时间只能启用一个入口认证器，数据库也约束这一点。仅安装认证插件而未设置此绑定时，仍使用普通 Key 认证。

认证覆盖 Responses JSON/SSE、WebSocket 握手、Images、Search 与模型目录。API 只传递一个有效的 `Authorization` 头，最多 8192 字节；不传递 Cookie、管理会话或其他请求头。插件在 5 秒内返回 `authenticated`、`not_matched` 或 `rejected`，其中 `authenticated` 只能包含外部 principal。宿主查询明确配置的 Key ID，再由 Core 检查当前启用状态和权限，使用该 Key 所属用户的分组、倍率、共享预算与正常结算。

默认策略为 `reject`。选择 `delegate` 后，仅插件明确返回 `not_matched` 才尝试普通 `sk_` Key；插件拒绝、返回未知身份或绑定 Key 无效返回 401，超时、崩溃、非法响应或恢复失败返回 503，不静默回退。普通 Key 回退保留原认证策略，不允许在密钥轮换过程中只凭旧 Key ID 获得新策略授权。

启用、停用、更换配置或版本会撤销旧入口授权，包括原本使用普通 Key 或回退认证的长连接；客户端需重新认证。失败升级保留旧认证器及旧授权，进程退出则撤销其授权。失败启动保留认证门禁，管理员可修复配置或停用后恢复普通 Key 入口。SSE 即使停止拉取正文，WebSocket 即使空闲，也会观察撤销；已产生费用按正常链路结算。

认证不改变管理登录。管理员会话、管理 API Key 和插件页面的本人选 Key 推理沿用原有权限入口，因此认证器出错时管理员仍可修复它。认证阶段可使用当前实例的 `host.state.get/put/delete` 和通用外部 HTTP，没有管理操作者身份，不能调用管理事实、资源创建或额度修改回调。

配置保存在迁移 `0030_plugin_frontend_authentication.sql` 增加的实例字段中，随完整 PostgreSQL 备份恢复。映射中的身份不会写入审计详情；插件必须自行避免输出认证信封和令牌。当前已验证真实 SDK 进程的认证调用与管理生命周期，以及 HTTP／WebSocket 的宿主映射和撤销；这不表示任意第三方认证插件的所有依赖回调均受支持。

## 限制与数据

单包最多 32 MiB；制品总量最多 128 个 / 512 MiB；最多 64 个实例。管理资源单个最多 1 MiB、注册资源合计最多 8 MiB；管理请求和响应正文最多 1 MiB。资源必须在清单和管理注册中声明，页面不得加载外部资源或嵌套 iframe，脚本须打包为普通脚本而非 ES module。

私有状态最多 16 个命名空间，每个最多 4096 条、4 MiB，单值最多 256 KiB，实际采用清单与宿主共同约束。版本切换不允许改变状态声明；需要迁移的插件版本当前不能原地升级。私有状态不能作为本地用户额度或账本的替代权威。

迁移 `0027_plugins.sql` 追加制品、实例与私有状态表，不修改已有迁移、用户归属或用户＋分组账本。完整 PostgreSQL 备份包含这些表；运行目录下的插件解包缓存可从数据库制品重建。恢复后仅启动已启用实例，单个插件启动失败不阻止网关启动。

## 后续改造边界

只读事实、实例自有分组/Key、显式共享额度管理和 management 原生模型回调已接入；后续继续接入完整深度扩展与具体业务插件。现有差异功能尚未从主程序移出。用户、共享账本、请求结算和 Provider 凭据归属继续由核心模块负责。

本轮实际运行验证平台为 Linux x86_64。CLI 可生成 Linux x86_64 / aarch64、macOS aarch64 制品，但本轮未完成其他平台的真实进程验证，不提供 Windows 插件制品兼容保证。

### Responses HTTP 接入进度

request 挂载已接入 Responses JSON/SSE 的认证后链路：插件可改写协议正文，宿主重新校验模型和续接信息，并保留原 Key、请求 ID、截止时间及计费 owner。流式响应只有在整个首批改写结果有效且非空后才确认交付；原终态、费用和取消保持宿主所有。启用实例的撤销会中断正在等待上游的 SSE 并释放名额，响应改写失败不会抹掉已产生费用或自动重试上游。

这仍是分阶段接线：生产运行时继续拒绝启用 middleware，直到其余端点和传输等所声明范围完成验证。当前 HTTP 适配测试不代表任意第三方插件已兼容；非空计划的 JSON 总正文及 SSE 单批上限为 8 MiB，单批最多 1024 帧，无匹配中间件时沿用现有响应合同。


attempt 挂载已连接 Responses HTTP 和真实 SDK 子进程：每次重试独立调用，先校验并尝试登记原上游，再允许插件读取；费用、账号权限和续接状态由原执行链保留。插件可改写正文、客户端状态码和响应头，也可直接返回错误正文；改写不能改变已经冻结的模型、续接、storage intent、传输或能力需求。request 与 attempt 可同时挂载，仍只由原 Core 请求结算。

验证覆盖 JSON/SSE 透传、正文改写/展开、原始事实保留、错误短路、撤销与展开批次的交付屏障。非 2xx 错误正文可为原始字节，最多 8 MiB；JSON 来源最多保留 16384 个事件。这仍是生产启用前的接线验证，middleware 能力门禁保持关闭，尚不能直接启用任意第三方中间件。


### Images 与 standalone Search 接入进度

request/attempt 两层已接入 `/v1/images/generations`、`/v1/images/edits` 和 `/v1/alpha/search`，并通过真实 SDK 子进程的透传、事实读取、正文改写和错误短路测试。它们固定使用 OpenAI Provider 原生端点；图片生成/编辑类型由入口保持，正文中的模型不参与文本模型映射。插件输入与输出继续过滤受管身份头；attempt 仅重建原端点已有的 session、thread、turn metadata 和 image turn 请求头。

未改写的响应保留原始 JSON 字节、空白和字段次序，不包装成 Responses 对象。插件可修改客户端状态及正文，但不能修改原上游状态、费用和结算身份。请求取消、插件撤销、非法输出和超限均沿用同一 Core 清理路径。生产 middleware 门禁仍关闭，其余声明范围尚待接入；经过中间件的 JSON 文档仍受 8 MiB 上限约束，大图响应可能超限，无匹配中间件时保留原有大响应合同。


### WebSocket request/attempt 接入进度

Responses WebSocket 的 attempt 挂载已接入原 Core 执行与控制帧转发链。每个插件正文帧是一条完整 JSON 消息，不使用 SSE 字节；插件可改写消息内容或展开消息，宿主按整批校验后交付。原响应 ID、冻结模型、续接、stream 语义、连接 ID、上游传输标记与 Provider 私有状态保持原归属，避免把响应中断或下一轮续接指向其他执行。错误短路的 JSON 对象投影为带非 2xx status 的 WebSocket error 消息。

真实连接验证覆盖响应中断、错误 ID 拒绝、排队 create 串行执行、断连/撤销、原生续接状态和改写批次失败；SDK 子进程验证 JSON 消息透传、改写、展开及错误短路。等待 WebSocket 写入时仍检查插件撤销；Core 启动后、首次轮询转发前发生撤销也会释放并发并完成唯一结算。request 与 attempt 现已同时接通，共用同一根请求、交付屏障和费用 owner。生产 middleware 能力仍未开放，后续继续接入执行设置、嵌套宿主调用与其余声明范围。


request 插件获得不含 `response.create` 类型字段的请求 JSON，可以在正常 Core 权限与路由检查前改写模型和正文；客户端流式语义、连接身份、上游传输标记仍由入口保持。宿主按改写后的续接 ID 选择连接内私有状态，不从插件正文恢复状态。响应以完整 JSON 消息批次校验，不发送 SSE 的 `[DONE]`，只有通过校验才确认原交付；原始响应 ID 和费用不能被改写。

等待 request 插件、Core 启动及下一批响应时，复用原控制帧 pump，保持同一个读取 future，排队 create 仍串行执行。关闭连接、禁用插件或换代会中断等待并交还原清理 owner。request 层直接返回错误时不会启动 Core 或产生费用；attempt 层错误短路仍由已启动的 Core 请求收尾。容量不足的 503 与客户端续接重放错误复用原 WebSocket 投影，不被 request 插件链改成普通错误。真实连接覆盖三种挂载组合、next 前后挂起及改写续接后的私有状态隔离；真实 SDK 子进程与 Core 验证两层正文改写/展开、唯一交付确认和原始费用。


### Request 能力转换声明

Responses JSON/SSE/WS 的 request 层已接通 SDK `declare_capabilities`。声明必须与显式正文替换一起提交；`handled` 只能包含本层输入确实需要、替换后正文已不再需要的 tools、vision、reasoning、json_schema。重复项、空声明、handled/required 重叠、没有实际消除的功能都会被拒绝。转换后的响应还原由插件负责。

Core 路由仍校验改写后正文中的全部需求，并继承链入口中未声明处理的需求及各层额外 `required`。后层重新引入的功能会恢复检查，不能取消前层的额外上游要求；原生续接不能声明为已处理。attempt 重解码保留继承的声明，但继续独立比较实际正文的能力，不能在已选路由后借声明修改能力范围。声明仅用于 Responses request；attempt、Images 和 Search 会明确拒绝。

这项接线经过 SDK 子进程、嵌套 next 与本地 Core 路由验证，覆盖 HTTP JSON/SSE 和 WebSocket 两层组合。它不解除 middleware 生产启用门禁：宿主模型调用及其余声明范围仍在实施。


### 请求级运行设置基础

Core 已建立与持久化快照共用的 `SettingsValues`，覆盖本地已有的价格、模型映射、账号调度和最低客户端版本事实。`RequestSettings` 为每条调用分支保存宿主基线、有效快照及逐字段的插件来源/顺序；嵌套替换不修改父分支或其他请求，切换宿主基线时只继承显式改写，映射对象整体替换。

`PreparedRootExecution` 已能在原身份、权限、取消和期限下使用派生快照规划模型或固定 Provider 端点；不会重新认证、更新全局 revision 或建立另一个账本。基线不匹配和已撤销请求会被拒绝。SDK request 阶段已接通完整 settings 替换，Fast、Key 准入、运行设置及期限沿原执行链生效；attempt 的 settings 保持 null，只提供有效设置来源。可用 runtime 字段以本地宿主返回对象为准，不支持的字段会明确拒绝，不能据此推断上游设置插件无需适配。


### 执行设置的 Fast 与准入

请求设置新增按 Key 隔离的 `ExecutionSettings`。Fast 和 Key 并发/RPM 改写保留实际插件来源及顺序；切换 Key 时清除旧 Key 的执行覆盖，原客户端策略及用户共享准入限制保持原权威。Core 在原准入/预算/结算路径中使用有效 Key 限额，并在每次真实 attempt 中传递冻结的 Fast 模式。

OpenAI Provider 在 attempt 插件之前形成应用 Fast 策略的原生正文：`default` 原样保留，`enabled` 只在冻结模型目录明确提供 priority 且客户端未指定档位或使用 default/null 时改为 priority，`disabled` 把 priority/fast 改为 default；flex、auto 和其他显式值保留。attempt 插件的后续显式改写不再被 Fast 覆盖。原协议上下文、私有续接和继承能力约束保留；其他协议及 Images/Search 不应用 OpenAI 文本档位规则。费用仍取上游实际档位，缺少实际档位时按最终发送档位计算。

HTTP、WebSocket wire 与费用回归已覆盖这些规则，Core 验证重试、唯一结算和共享用户限额。SDK 执行设置入口已接入；生产 middleware 门禁仍保留。超时支持非负毫秒数或 null，0 在终端准入前立即到期，null 表示不设总期限。


准入租约已接入持续续期，覆盖 Key 与用户共享并发作用域。取消后的异步结算仍保留槽位；租约丢失会取消原执行，已释放或过期槽位不会通过续期重建。普通请求不再附加固定总期限；SDK request 超时改写从原请求开始计时，不重置时钟。


PostgreSQL 执行记录已具备持续恢复租约：复用原 running 行，延迟入队的创建记录不会被续期补造，最终状态不会被复活。Core 在终态持久化完成前保留 guard；异常退出停止续期后由既有回收器收敛。恢复租约可有独立的有限执行上界或无上界，Core/Provider 实际执行链已支持该可选期限；插件 SDK request 设置写入复用相同生命周期。


### 可选执行期限

普通请求默认没有总时长上限。Core 请求分支可显式设置非负毫秒数，始终从原请求开始时间计算；null 移除总期限，改写不更换身份、取消信号或费用归属。OpenAI 文本/Images/Search 与 xAI 推理/压缩均传递可选截止时间，连接预算、握手和接收空闲超时仍各自生效。插件页面桥保留 10 分钟调用限制，RPC 保留单次调用上限。

Provider 账号调度槽位现已随其 fenced guard 自动续期；不会重新选号、增加并发数、重置调度间隔或获得新的 fencing token。释放前停止续期，租约丢失取消原请求，显式期限到达由 Core 判定 timeout。PostgreSQL 的 deadline_at 用于有限恢复租约，不以虚构远期时间表示无限执行。SDK request 设置值与来源视图已接线；生产 middleware 门禁继续保留，等待其余声明范围完成。


### SDK 执行设置传递

request 的 settings 是当前有效的完整对象，包含 runtime、fast_mode、client_limits、timeout_ms。只有实际改变的字段记录插件来源及顺序；同一层运行设置与执行设置使用同一顺序。来源 ID 来自宿主会话，修改 settings_sources 不能伪造其他实例。后层读取前层的结果，原入口与后续请求不受影响。

Responses JSON/SSE/WS、Images 和 Search 的终端都通过原 PreparedRoot 应用设置，再执行路由、准入与结算。attempt 及 Provider 接收最终冻结的 RequestSettings，重试使用相同来源；attempt 不开放设置改写，避免在准入后改变已确定的权限和执行归属。未知字段、缺失设置作用域及非法类型会拒绝，不进行隐式深合并。

runtime 是本地执行设置合同，当前包含计价、账号并发与间隔、轮转策略、模型映射、客户端最低版本。上游特有的画像、位置、Guardian 等字段尚无对应实现；最初入口已经完成的版本检查不会因后续设置改写重做。

### 原生模型子调用基础

Core 已提供宿主签发的父请求上下文，request/attempt 协议桥传递此上下文，正文或设置替换不能伪造父身份。子调用继承运行设置及来源；同 Key 保留 Fast、准入和超时覆盖，显式选择另一 Key 时清除这些执行覆盖，按所选 Key 的当前授权重新准备。父请求取消、权限撤销或结束后，持有旧上下文也不能继续调用；子调用不能延长或移除父期限。

每个根调用最多产生 64 个子调用，同时最多 16 个活动子调用，最多 8 层插件祖先；发起插件及全部祖先从子请求的 request/attempt 计划中排除。并发占用保留至原结算和清理完成，保留旧上下文不会锁住已结束的占用。子调用使用自己的请求 ID、原账本和准入链，历史记录保存父请求与发起实例；父记录尚未创建也可记录子调用。观察到子调用上游发送或不确定发送后，父请求不再自动重试。

原生 `host.keys.list`、`host.models.list`、`host.model.execute`、`host.model.execute_stream`、`host.model.stream_read` 和 `host.model.stream_close` 已接通。管理调用必须由本人管理员会话发起并显式选 Key；Key 列表只返回本人非秘密信息，部署级管理 API Key 或管理阶段的 System 没有个人推理身份。宿主系统命令使用独立的全局非秘密 Key 投影，并以显式 Key ID 绑定原 Core 授权；客户端或插件声明 stage/actor 不能签发此权限。request/attempt 内核中的子调用可以继承宿主签发的父身份；显式 Key 继续由 Core 检查其当前授权，父身份结束或撤销同样终止子调用。

管理调用中的推理没有虚构的模型父请求，仍共用调用图限额并排除发起实例；其管理调用上下文保留真实实例与操作者。显式 Provider/账号不得超出 Key 范围，子调用排除父 attempt 已持有的账号；没有其他授权账号时立即失败。续接账号与显式目标冲突时拒绝，不能换号发送原生续接。

请求正文与 HME1 事件批次最多 8 MiB，每个 RPC 范围最多 16 个活动模型资源。流句柄只属于创建它的宿主调用；结束、取消、停用、换代或进程退出时撤销并交回 Core 清理。一次读取保持完整事件批次，maximum_bytes 太小返回 capacity 并保留待交付批次，调用者可加大上限再读；end=true 仅在原终态、结算和准入释放完成后返回。RPC 取消不会丢掉已开始的准入、交付提交或结算。

当前原生模型协议支持 openai，Generate 走现有模型路由；Images generation/edit 与 standalone Search 沿用本地固定 OpenAI 端点，不参与文本模型映射。它们的正文模型若存在必须与 SDK 元数据一致，仍由 Provider 解释原生正文；续接仅允许 Generate 且元数据必须匹配正文。认证、命令、维护和观察阶段的原生模型回调尚未开放。

账号排除由 Core 的活动 attempt 提供：Provider 在 next 后选定账号，Core 校验冷流元数据后保留只读账号事实；事实随原 attempt 的释放失效，不延长账号租约或父请求。子调用路由与每次 Provider 启动前排除所有仍占用账号的模型祖先，显式目标和续接 pin 也不得绕过。冻结路由后父账号才确定的调用，在原 attempt 启动边界再次检查；无可用替代账号直接拒绝，不能等待父请求释放自身账号。若已进入 Provider 选号等待，相关祖先新占用候选账号时撤销旧等待，以 not-sent 的无可选账号错误收尾；不自动重启中间件 next，原结算和清理继续执行。候选范围外的祖先账号变化不撤销合法等待。静态回调 account_id 仍可进一步收窄范围，插件 wire 不签发账号授权。

原生子调用已进入同一份冻结的 request/attempt 计划，发起插件和全部实例祖先由宿主排除。Responses JSON/SSE 与 Images/Search 复用现有 API 协议桥；插件改写后的正文投影为 HME1 返回，原会话继续拥有费用、账号、续接和交付提交。SDK 提前请求下一源时，在原提交屏障完成前等待；读取容量不足不会提前推进上游。只有外层终态及 Core 清理均完成后才返回 end=true。

已知 Provider 失败沿网关错误保留发送状态和 HTTP 状态码；无法证明发送状态的中间件启动失败使用 ambiguous，不能据此自动重放。管理调用中的模型与孙调用已通过真实 SDK 子进程和本地 Core 验证，包含两层改写后原费用只结算一次、祖先排除、错误短路、提交中取消、next 后不依赖 wire 账号 ID 的模型回调，以及路由冻结后才确定祖先账号时的拒绝或改选。其余挂载、上游适配器与目标插件兼容验收仍在实施，生产 middleware 和 upstream_adapter 启用门禁继续保留。这不构成任意上游插件完整兼容的承诺。

子调用已经发送或发送结果不确定后，父请求的未发送选号失败也不能自动切换 Provider 或改为原生续接重放；子调用明确未发送时保留原有恢复策略。父请求在重试退避期间才观察到子调用发送时，启动下一次尝试前会再次检查，并返回原失败及其保留的客户端事件，继续原结算和释放流程。子调用的发送事实只限制祖先重放，不改变父请求自身的发送状态或费用归属。

## 账号调度

声明 `scheduler` v1、`scheduling` 阶段的制品可在管理页配置账号调度绑定：顺序、全部请求或指定 Key/分组，以及故障时拒绝或使用宿主调度。绑定保存为实例字段 `accountScheduler`，不混入插件配置；迁移 `0036_plugin_account_scheduler.sql` 随完整备份恢复。顺序较小者优先，同序号按实例 ID 排序，只调用首个匹配的实例；未匹配、明确 Delegate 或显式故障委托均使用宿主选号，明确 Reject 会终止请求。

`policy.schedule_account` 仅接收宿主合格候选的账号 ID、权重、并发、额度重置/排序及健康指标，没有凭据、请求正文和二进制载荷。Pick 必须位于该次候选集合；Key 的账号/模型权限、Provider、原生续接硬绑定、时间资格及实际账号租约仍由宿主检查。插件故障和明确拒绝不会当作账号不足换 Provider，软亲和绑定也不能覆盖显式 Pick。

调度 RPC 有独立的两秒上限，且不超过请求剩余期限；普通请求没有总期限也不会无限等待插件。调度阶段允许实例私有状态、通用外部 HTTP 和绑定父执行的原生模型回调，拒绝管理事实、资源创建及额度修改。子调用使用原 Key 权限、独立费用和全部插件祖先排除。已成功咨询的进程代次在 RPC 返回后继续关联原请求取消链，停用、换代或进程退出会结束执行，并结算此前已经观察到的费用。路由和调度共用请求撤销源，Core 已结算但尚未交付的缓冲 JSON 同样受它保护；正常结算不会撤销成功输出。升级准备失败保留旧代次及旧绑定。

## 重试策略

Core 已提供 `RetryPolicy` 裁决端口：只投影安全失败事实、冻结 Key/分组与插件祖先范围，以及宿主当前允许的恢复动作。Stop 阻止恢复，Delegate 和 Retry 只能继续宿主已选定的路径，不能改变账号、传输、服务端退避或预算；故障及独立两秒等待上限到期均委托原策略。发送不确定、缺少重放证明、已经提交、预算耗尽或子调用已产生副作用时，插件 Retry 无法开启重放。固定账号诊断不咨询插件策略。

裁决等待保存在原 Core 执行会话中，保留失败、账号持有和原始事件；临时丢弃读取不会重复 RPC 或 Provider 准备。请求取消、期限到期和成功咨询代次撤销仍由原终态与费用 owner 处理，裁决返回后再次检查子调用副作用及连接预算。准备阶段没有可用账号时的跨 Provider 恢复也接受同一裁决。声明 `retry_policy` v1、`retry` 阶段的制品可配置实例字段 `retryPolicy`：顺序、全部请求或指定 Key/分组；绑定随迁移 `0037_plugin_retry_policy.sql` 备份和恢复。冻结范围及全部发起祖先决定匹配集合，按顺序与实例 ID 咨询；Delegate 和故障继续咨询下一个匹配策略，Stop 或 Retry 结束链路。没有成功裁决时委托宿主恢复。升级候选准备失败保留旧代次与绑定。

`policy.retry_decision` 只传请求关联、尝试序号、Provider/模型、错误分类、状态码、发送状态、剩余路由预算与期限，以及宿主允许的动作；不传请求正文、凭据或上游错误正文。回复必须为一个决定字段且没有二进制载荷，额外字段或宿主不允许的 Retry 均视为故障。整条策略链共享两秒等待预算，每次 RPC 继续扣除已用时间，并受请求剩余期限约束。

retry 阶段允许实例私有状态与通用外部 HTTP，仍禁止原生模型、管理事实、资源与额度操作。HTTP 的已发送或不确定发送效果进入原 Core 调用图，阻止自动恢复。每次成功咨询立即加入原请求的策略撤销源；在后续策略等待或恢复后的执行期间，前一代次崩溃、停用或换代都可撤销请求。该源同时保护 Core 已结算后的缓冲 JSON 交付，正常结算不会撤销成功输出。JSON/SSE/WS 与原生模型调用通过同一 PreparedRoot 绑定使用该策略。

## 维护任务

声明 maintenance v1 的已发布实例运行 plugin.reconcile：启用、配置发布后触发对账，空闲时每 30 秒运行一次，失败后等待 5 秒重试。每个实例串行执行；单次 RPC 最多 30 秒。故障实例不会阻塞其他实例，子任务异常由 Host 按 1～30 秒退避重启守护任务。

准备候选、校验、未确认提交的版本不会启动维护。停用、换版、进程退出和宿主关闭会取消旧调用，排空后才启动新发布批次。Core 快照不可用时暂停维护；即使暂停和恢复通知被合并，旧可用期的授权仍立即撤销。Core 重复发布同一配置 revision 不触发额外对账，避免幂等资源查询发布相同快照造成紧密循环。

维护调用可使用实例私有状态、通用外部 HTTP、只读事实、已接入的设置服务和实例自有分组回调。服务发布在原 RPC 开始前冻结，实际审计使用插件实例及 revision，取消、期限与调用结束清理贯穿回调。维护任务不取得管理员会话；创建本人 Key 和修改本地共享额度仍需要原管理授权。维护阶段原生模型回调尚未开放，不能借用其他管理请求或伪造父执行。

固定上游 SDK 的维护调用与类型化服务中间件，以及实际数据库写入、插件审计和 Core 发布有独立验收；这不代表 workbench 原包或其全部回调已经兼容。
