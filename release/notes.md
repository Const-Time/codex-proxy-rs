# v3.12.2

## 插件兼容与稳定性

- 修复模型调用事件中的本地扩展字段导致上游 SDK 拒绝整个事件批次的问题，覆盖普通响应、流式响应与小批次读取。已使用 model-health 插件固定的 SDK 版本验证解码；宿主的分范围倍率计费、共享额度、用户权限和账本继续由核心负责。
- 修复插件异常后无法停用或删除的问题，并提供删除入口。停止插件时回收其子进程，减少反复启停后的残留资源。
- 限制插件归档校验的资源使用，避免运行时长期保留归档和可执行文件副本；列表与元数据查询不再加载完整制品。

## 性能与资源使用

- Responses、Images 和 Search 在读取正文前完成鉴权；新增共享上传缓冲预算、并行上传数量和上传超时，减少大正文请求造成的内存压力。
- 密码计算改为有界专用工作线程，并限制登录尝试频率，避免登录压力阻塞正常请求。
- 相同权限与筛选条件的用量统计短时复用聚合结果；前端取消过期查询，API Key 并发刷新保留当前筛选条件。
- 优化授权策略索引和过期引用清理。普通应用日志使用有界非阻塞队列，过载丢弃整条日志并报告健康状态；恢复日志和显式报文转储仍保留背压。

## 费用结算与部署

- 增加待结算费用的持久化投递日志，重启后按请求 ID 幂等补入 PostgreSQL，避免数据库短时不可用或进程退出导致已产生费用丢失。
- 请持久化并随实例数据备份 `host.runtime_data_dir/budget-settlements`。仅备份 PostgreSQL 不包含尚未投递的费用；不要清空该目录来绕过恢复失败。标准 Compose 已挂载运行数据目录。
- Compose 默认 CPU 上限调整为 1 核，兼容单核服务器；可按宿主机实际资源调整。

## 构建与验证

- 测试构建单独优化哈希和压缩依赖，统一测试及专项检查的 workspace/features 构建图，减少重复编译；流水线拆分编译与执行计时，保留现有检查。
- 修正原生适配器回归测试对账号请求间隔的等待，避免运行加速后出现测试竞争。
- 本地已通过后端相关测试、377 项插件运行时测试、前端 67 项测试、构建、严格 Clippy、格式及工作流静态检查。共享额度插件打包验收及固定上游 SDK 解码通过。
- 未调用真实模型执行完整检测；原生插件仍属于可信进程扩展，本版本不提供每插件 CPU/内存硬隔离。
