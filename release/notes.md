# v3.7.3

## 用量与缓存趋势

- 概览的用量趋势增加缓存读取、缓存写入和缓存命中率，与输入、输出 Token 同时展示。
- 使用记录增加“Token 用量 / 请求健康”切换，默认展示用量趋势，保留原有四块卡片布局；使用统计同步采用相同展示。
- 点击指标可单独查看对应趋势，再次点击恢复全部。Token 使用数量坐标轴，缓存命中率使用百分比坐标轴。
- 命中率按所选范围内的总缓存读取 Token 除以总输入 Token 计算，不直接平均分段百分比。没有输入时显示“—”，稀疏采样仍显示有效数据点。
- 补齐趋势接口的缓存写入数据；缓存读取和写入独立展示，不重复计入总 Token，个人使用记录继续只展示当前用户的数据。

## 操作日志来源 IP

- 操作日志列表改为展示“来源 IP”：优先显示代理上报地址，并保留应用直连对端 IP。经 Docker 或反向代理转发时，不再只看到重复的网桥地址。
- 在原有 X-Forwarded-For 支持基础上，兼容 X-Real-IP 和 CF-Connecting-IP；只记录格式有效的 IP，不保存原始请求头。
- 代理上报地址明确标注“未验证”，保持与直连地址分离，不改变鉴权行为。没有来源头时显示“未上报代理来源”，历史缺失地址无法补回。
- 部署文档补充转发来源头与代理链排查说明。

## 验证

- 用量观测相关的 40 项后端测试、2 项前端计算测试通过，前端计算测试已接入 CI。
- 本地浏览器验证概览与个人使用记录的缓存指标、指标单独查看、请求健康切换、空数据和单个命中率采样点。
- 操作日志回归测试通过，覆盖 IPv4、IPv6、转发头优先级、无来源头、非法来源头及身份隔离；严格 Clippy、前端 lint、类型检查和生产构建通过。
- 本地浏览器验证代理上报地址与直连地址同时显示，并核对无来源头时的提示。
- 不新增数据库迁移。包含 v3.7.2 的额度区间估算、分组用户数、订阅排序和更新错误提示修复。
- Docker：`ghcr.io/const-time/codex-proxy-rs:3.7.3`，支持 Linux amd64、arm64；正式发布后同步更新 `latest`。
