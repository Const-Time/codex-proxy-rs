# v3.10.1

## WebSocket Turn-state 接管

- 现有账号级接管开关同时适用于 HTTP 和 WS，不增加第二套维护器，不强制 WS 降级为 HTTP。已开启接管的账号升级后，符合条件的 WS 请求即可使用有效候选。
- 每次独立 `response.create` 在实际选定账号后读取该账号、精确模型及当前鉴权身份下的候选；写入请求帧的 `client_metadata["x-codex-turn-state"]`，不写入 WS 握手头。指纹收敛关闭时同样生效。
- 同一连接复用时，每次独立请求重新检查资格，不把候选或“已接管”标记保存在连接级上下文。其他 metadata、业务正文和原有传输选择保持不变。
- 同轮请求、`previous_response_id` 和原生续接不重新选取候选，继续按原有会话规则传递状态。已有 WS 会话缺少上一轮或本轮 turn ID 时，不把未知轮次边界当成新请求接管。
- 非对象 `client_metadata` 无法安全投影时跳过 WS 接管，不强改用户数据，也不把未发送的候选记成已发送。
- 关闭接管、撤销候选、跨账号或更换鉴权身份后，后续独立请求不再使用旧候选；候选缺失不禁用业务账号。
- 维护探测仍使用原有 HTTP 采集/验证流程，保留预算、空闲限制、绝对有效期和限流冷却。WS 返回值只用于当前响应观测及会话续接，不自动加入维护候选池。

## 使用统计与界面

- 使用记录及错误列表的维护探测显示“系统维护”，并说明消耗上游额度、不扣用户额度；其他没有用户身份的记录显示“无用户归属”。正常用户名和邮箱不变。
- 用户排行的无归属聚合项不再误表示为真实用户，也不会一律标为系统探测。
- 维护页明确显示“候选可用”和“HTTP / WS 接管已开启”，区分候选准备状态、开关状态与单次请求实际注入结果。
- 请求详情保留实际发送值及“接管”来源，并分别展示上游返回状态。上游返回 312 等长度变化不等于没有注入，也不是模型能力判定。

## 升级须知

- 本次无新增数据库迁移，不修改已有 0001–0023 迁移。保留 v3.10.0 的分组额度、统一周周期及原有数据。
- 全局维护、账号接管、维护项和代理池需要开启，且对应账号/精确模型有有效候选。所有开关仍默认关闭。
- 升级前备份数据库、配置和身份密钥，继续使用原有 `identity_hmac_secret`。接管不是上游协议保证的能力，不保证改善模型质量。
- 验证时请使用新的非续接请求，查看请求详情的“实际发送”来源是否为“接管”；不要只凭列表中的返回值字符数判断。已有原生续接不强行覆盖。
- 仅发布软件包与镜像，不自动升级或重启线上实例；不补写历史 State，也不自动修复历史错误清零额度。
