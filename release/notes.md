# v3.6.0

## 用户订阅与额度

- 用户编辑支持为每个授权分组配置独立额度倍率。例如原周限 100 美元，用户设为 2 倍后周限为 200 美元，日限同步调整；不改变消费计价，其他用户不受影响。
- 在分组管理下新增订阅管理，显示用户分组、有效日周限额、已用额度、下次刷新、最近重置时间与原因，支持用户名和分组筛选及分页。
- 管理员可一键重置所有当前用户订阅配额，保留历史请求和消费账本；请求重试幂等，在途请求仍正常结算。
- 账号主动重置成功，以及观察到上游自行重置或自然窗口恢复时，联动关联分组下全部用户的日周额度。后台每分钟检查已取得的上游配额，首次观察、重复及过期快照不清零。

外部重置依赖上游快照中的窗口边界推进，或已用比例从至少 5% 回到不高于 1%；上游未刷新或无法观察到的变化不能保证识别。自然窗口的延迟检测保留重置边界后已产生的消费。

## 计费明细与界面

- 修复配置分组模型倍率后，原始模型价格校验失败、计费明细只剩总额的问题。原始分项、单价、服务档位倍率、冻结的分组模型倍率和最终费用分别展示。
- 使用统计、个人使用记录的金额去掉“≈”符号；无法恢复单价的历史请求仍显示原始总额、分组倍率及最终费用。
- 用户管理使用用户组图标、账号管理使用服务器图标、个人资料使用个人图标，避免混淆。

## Codex Fast 适配

- 修复上游模型目录中的 Fast 服务档位在解析时被丢弃的问题，保留能力声明和档位名称；未声明支持的模型不自动启用。
- 密钥使用配置增加默认 Fast 开关，标准模式仍为默认值；配置启用 `features.fast_mode`，请求中的档位继续原样透传。
- Codex App 还会限制非 ChatGPT 登录方式的速度菜单。该客户端限制不能由网关修改，代理密钥用户可通过生成配置设置默认档位；是否支持以实际客户端和上游响应为准。

## 验证与升级

后端全工作区 2,017 项测试、真实 PostgreSQL/Redis 集成测试、Clippy、前端类型检查和生产构建通过。完成本地接口和页面验收，覆盖用户隔离、额度倍率、幂等重置、上游恢复去重、历史消费保留及倍率计费明细；补充 Fast 目录能力、服务档位透传回归测试。

升级自动执行新增迁移 0011，已有用户额度倍率为 1，不修改旧迁移及历史金额。升级前备份数据库；回退旧版本时恢复对应数据库备份。

Docker：`ghcr.io/const-time/codex-proxy-rs:3.6.0`，支持 Linux amd64、arm64，`latest` 同步更新。
