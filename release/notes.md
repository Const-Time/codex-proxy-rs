# v3.10.0

## 版本调整

- 本版本替代并撤回误用版本号的 v4.0.0，保留其功能与提交历史，合并本次 State / 指纹修复及分组额度适配。不是把代码回退到旧版。
- v3.10.0 发布成功后撤下 v4.0.0 的 GitHub Release、Git 标签和 `4.0.0` 镜像索引；`latest` 指向 v3.10.0。已运行的旧实例不会被自动修改。

## Codex 指纹与 Turn-state

- 保留账号级独立的「指纹收敛」和「接管 turn-state」开关，默认关闭。仅接管 HTTP 非原生续接请求，不强制 WebSocket 降级，不修改用户正文。
- 候选绑定账号、上游身份、访问令牌和安装身份，不再因普通 Cookie 更新而失效；换鉴权身份后旧候选不可用，旧请求迟到结果不能重新填回。
- 保留候选绝对有效期；改名称、调度频率或预算不续期。修改筛选形态、TTL 或出口配置后重新验证。
- 重新 OAuth 授权检查上游身份，避免误登录其他账号覆盖原凭据。
- 最终 HTTP、SSE、WebSocket 容量错误统一交付为可重试的服务端错误，不改变正常续接和重放策略。

## 有界维护与使用统计

- 每账号默认每小时最多 30 个探测请求，采集与验证分别计数；预算、轮询游标和冷却持久化，重启、手动刷新不重置预算。
- 默认空闲一小时停止自动探测；自动发现精确业务模型默认关闭，开启后仍受账号/全局数量上限约束。
- 支持固定出口、轮换入口和 HTTPS 代理提取；业务出口验证使用账号自身出口。仅收到正常完成响应才发布候选，HTTP 200 或状态响应头本身不代表成功。
- 尊重 HTTP/SSE 限流及 Retry-After，按账号冷却；认证失败只暂停维护，不停用业务账号，不以立即切换出口或模型绕过拒绝。
- 使用统计保留 turn-state 字符数、完整值复制、实际发送/返回值及来源；系统维护探测可单独筛选、审计，并记录真实上游用量，不扣用户额度。未知费用不伪造为零，普通用户不能读取内部状态原文。
- 未移植全局/Key 六套客户端画像，也不调整模型定价。长度只是结构观测，不代表模型能力。

## 分组额度与统一周期

- 自动联动开启且分组恰好配置一个账号时，跟随该账号上游周窗口。到达预期边界但未确认上游重置时，保留并继续累计用量和执行限额，不提前清零。
- 多账号分组（含停用成员）、无账号分组或关闭自动联动时，使用分组统一的独立七天周期；新订阅沿用组周期，单个成员上游重置不再清空整个池化分组的额度。
- 独立周期由下次准入或结算推进，组内已有订阅同步换周；成员/开关切换保留当前用量。
- 手动重置仅影响选中订阅，不移动分组统一结束时间，不影响其他订阅；保留账本、迟到结算归属及幂等性。
- 日窗口仍按北京时间零点换窗。只读页面不再因时间到期虚假显示零用量；实际日/周换窗记录原因与受影响订阅。

## 升级须知

- 从 v3.9.x 升级会追加 `0022_turn_state_management` 和 `0023_subscription_group_cycles`；已升级 v4.0.0 的实例仅追加 0023。已发布迁移原始内容与校验值不变。
- 本次 v4.0.0 → v3.10.0 属于同一代码线的版本号纠正，不要求清空数据库或重新导入账号；下方通用的跨大版本全新部署警告不适用于这次纠正。
- 升级前备份数据库、配置和 `identity_hmac_secret`，继续使用原有身份密钥。新维护文档和数据库迁移不保证旧二进制可读；回退应恢复对应备份，不要只替换二进制。
- 开关默认关闭，主动探测消耗上游额度；在进行中会话结束后再切换指纹模式。跨实例同步不是瞬时完成。
- 不自动补回旧版本已错误清零的额度，也不补写历史空白 turn-state；应另行确认正确周期边界后从账本修复。
- 只发布软件包和镜像，不自动升级线上实例。
