# v3.8.3

## 额度估算更新

- 修复新采样存在缺失费用时，旧的 1 个百分点估值长期不更新的问题。新采样有可用费用即更新参考值，并标明缺失笔数与“估值可能偏低”；只有完全无法计算时保留上次结果。
- 保留旧值或存在缺失数据时，仍显示样本不足提示。已有 v3.8.2 采样状态可在后续补算中恢复，不需要清理数据。

## 上游稳定性修复

- 合入上游 #90、#99：将 SSE 和 WebSocket 客户端无法消费的裸错误投影为 response.failed，保留错误字段与 response 身份，避免客户端忽略上游失败后继续空等。已可消费的 WebSocket 包装错误和续接错误继续透传。
- 合入 #89 及其后续修复：可安全重放的账号级拒绝交回 Core 换号；明确的过载、容量不足先做有限同账号退避，再通过现有调度换号，保持总尝试次数与截止时间约束。
- 合入 #95：同一额度窗口内用量回落后，连续两次有效观测可解除对应耗尽状态。额外收紧恢复证据，缺失百分比、缺失或更旧的重置时间不会导致误恢复。
- 合入 #87：对齐 WebSocket 业务请求头顺序，并验证原始握手、压缩协商与帧结构；不改变 TLS 依赖版本。

## 管理端

- 合入 #81：上游仅返回可用重置次数、没有卡片明细时，也能经确认使用一次重置，由上游选择卡片；继续使用 UUIDv4 幂等标识。
- 合入 #73：普通 HTTP 部署支持登录会话和复制回退。HTTPS 或无法确认来源时继续使用 Secure Cookie，并保留本分支的邮箱登录、用户权限和退出审计。

## 验证与升级

- 后端全量 2,092 项测试、前端 6 项测试、严格 Clippy、前端 lint、类型检查和生产构建通过。
- 全部 17 个已发布迁移通过冻结校验，不新增数据库迁移。
- 本次不加入自定义上游地址、Chat Completions、自定义密钥或计费档位口径变更。
- Docker：`ghcr.io/const-time/codex-proxy-rs:3.8.3`，支持 Linux amd64、arm64；正式发布后同步更新 `latest`。
