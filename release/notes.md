# v3.9.5

## 修复：Turn-state 请求值漏记

- 修复 v3.9.4 仅采集上游返回值、导致请求携带状态但响应没有刷新状态时明细仍显示空白的问题。
- 优先展示本次上游返回的有效 turn-state；没有返回值时，记录本次实际出站请求携带的值。HTTP 遵循实际透传头覆盖顺序，WebSocket 读取本次请求帧投影的状态。
- 请求明细和详情弹窗新增「返回 / 请求」来源标记，继续展示字符数、截断值及完整复制按钮；没有有效值时仍显示 `—`。
- 不使用已被账号/turn 安全边界清除的入站值，不跨请求借用状态，不把请求值伪装成上游响应头。
- 292、312、332、356 等长度均可记录；字符数只表示长度，不代表模型能力或健康状态。
- 普通用户的个人使用记录继续隐藏 turn-state 值和来源字段。

## 兼容与升级

- 无新增数据库迁移；新增请求从更新后开始使用修复后的采集逻辑。
- v3.9.4 已记录的状态继续按「返回」展示；历史空白记录无法自动补回。
- 不修改指纹收敛、状态注入、换号、续接或候选维护策略，不包含尚未完成的 turn-state 管理功能。
- 本次仅发布软件包与镜像，不自动更新线上实例；升级前建议备份数据库与配置。

## 验证

- 覆盖 HTTP 请求值兜底、透传头优先级、换号清除、WebSocket 连接复用不串状态、返回值优先和不同字符长度的回归测试。
- 覆盖 PostgreSQL 元数据读写、管理员 API 字段与个人使用记录隔离。
- 前端 30 项测试、格式检查、类型检查与生产构建通过；后端 2,158 项测试（含 PostgreSQL / Redis 集成测试）、格式检查及严格 Clippy 通过。
- 使用实际表格组件验证「请求 / 返回」标记、缺失值、字符数与完整复制。
