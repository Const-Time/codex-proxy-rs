# v3.6.1

## 配额重置修复

- 修复短周期窗口恢复或用量比例下降导致用户周额度被清零的问题。自动检测仅在账号级 7 天周窗口的刷新边界明确向后推进时联动；周边界未变不重置。系统内确认成功的主动重置仍会联动关联分组。
- 订阅管理按一个用户、一个分组一行显示，用户和分组使用独立列。
- 全体重置入口替换为多选批量重置，支持当前页全选及跨页选择。服务端按用户分组对精确处理，未选订阅不受影响；空选择被拒绝，同一请求重试不会重复清零。

## 管理员个人授权

- 管理员可在用户管理中编辑自己的授权分组和额度倍率。管理权限不变，不能修改其他管理员或禁用自己。
- 旧管理员首次保存前保留原有全部分组访问，保存后个人密钥按明确授权执行。取消授权即阻止对应密钥的新请求，自己的登录会话保持有效。

## 合入上游修复

- [#66](https://github.com/zyycn/codex-proxy-rs/pull/66)：支持 gzip、deflate、zstd 压缩的 Responses 请求，限制解压大小和内存窗口，拒绝无效或叠加编码。
- [#67](https://github.com/zyycn/codex-proxy-rs/pull/67)：剥离下游 Cloudflare、转发代理及传输层请求头，修复反向代理环境下的上游 WebSocket 握手失败。
- [#68](https://github.com/zyycn/codex-proxy-rs/pull/68)：保留上游模型的最大上下文长度，与默认上下文长度分开返回，同时保留本仓库 Fast 服务档位信息。
- 账号用量优先选择周窗口，其次月窗口，避免误用短期限流窗口。
- 修复普通 HTTP 页面主动重置不可用的问题，并将同一修复应用于订阅批量重置。
- 密钥用量列表金额不再补齐无意义的末尾零，明细保留原始精度。

## 验证

- 后端全量 2,042 项测试、严格 Clippy 和格式检查通过，包含压缩请求、WebSocket 请求头、上下文长度及用户分组权限和重置隔离回归。
- 前端 lint、类型检查与生产构建通过；浏览器验证管理员编辑自身分组、订阅独立行及多选确认范围。
- 验证普通 HTTP 环境的重置请求 ID 生成，并核对迁移 0012 及全部历史迁移校验和。

## 升级

自动执行新增迁移 0012，不修改旧迁移。升级前备份数据库。已发生的错误重置不自动反向改写，历史请求和消费账本保留。

Docker：`ghcr.io/const-time/codex-proxy-rs:3.6.1`，支持 Linux amd64、arm64，`latest` 同步更新。
