# v3.9.2

## 稳定性与兼容性

- 移植上游 `zyycn/codex-proxy-rs` PR #143：停用的 OpenAI / xAI 账号也能在管理端获取自身模型目录，补齐连接测试流程；普通调度与后台目录发现仍排除停用账号。
- 移植 #140：带 `previous_response_id` 的续写遇到明确额度耗尽时，在可安全重放、无语义输出且尚未提交下游的条件下，隔离原账号并投影 `previous_response_not_found`，由支持该协议的客户端携带完整历史重试，再由正常调度换号。
- 补齐本分支下游 WebSocket 恢复响应的状态码与响应头处理；保留真实上游错误用于诊断和记账，不向其他账号转发原增量输入。普通限流、容量不足、发送结果不明和交付后的失败不触发此转换。
- 移植 #134：Responses 请求缺少顶层 `store` 时补齐 `false`；显式值、嵌套同名字段及其他未知字段保持原样，HTTP/SSE 与 WebSocket 共用。

## 费用与模型观测

- 移植 #136：客户端请求 A、模型映射后发送 B、上游返回 C 时，本地模型估价按 B 的价格和实际用量计算；Provider 明确上报的已计费金额仍优先，B 无定价时保持费用未知。
- 独立记录 `upstreamResponseModel`，用量列表与详情区分发送模型和返回模型：蓝色箭头表示映射，橙色箭头表示返回差异，相同时合并展示。未报告的返回模型保持未知。
- 返回模型仅代表上游声明，不证明模型真实性；重试和 WebSocket 连接复用不沿用上一请求的返回模型。

## 兼容与升级

- 新增数据库迁移 `0021_upstream_response_model.sql`，启动时自动执行；升级前请备份数据库。
- 仅回填历史 OpenAI 记录中已保存的合法返回模型报告，其余历史记录保持空值，不重算历史费用。`0001` 至 `0020` 历史迁移及校验值不变。
- 保留本分支的服务档位、用户倍率、账本、额度估算与恢复、账号模型白名单及结构化代理配置。
- 本次未替换线上实例；发布包与镜像供管理员自行升级。

## 验证

- 后端 2,152 项测试通过，包含真实 PostgreSQL / Redis 集成测试、`0020 → 0021` 升级、续写恢复和换号、模型观测与计价、停用账号目录和 `store` 编码回归。
- 前端 26 项测试、lint、类型检查、生产构建及后端严格 Clippy、格式和迁移校验通过。
- 使用实际模型展示组件及隔离模拟数据检查浅色、暗色和窄容器长模型名截断；未使用真实上游账号进行生产端到端验收。
